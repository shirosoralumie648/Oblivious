# RC Checklist

This checklist is the minimum release-candidate gate for the current Oblivious mainline. It covers only `src/server`, `src/web`, `config`, `scripts`, `.github/workflows`, and release docs. `lobehub/` and `new-api/` remain reference trees.

Commercial readiness is a stricter gate than RC readiness. Use [`commercial-gates.md`](commercial-gates.md) before claiming commercial readiness or commercial completeness.

No live provider keys required for docs checks, web tests, server tests, or Admin/Marketplace E2E. Use placeholder environment values unless a deployment smoke target explicitly needs real infrastructure.

Commercial-readiness renewal additionally requires target/live evidence. Use `AGENT_GRPC_ADDR=... WORKFLOW_GRPC_ADDR=... TASK_GRPC_ADDR=... bash scripts/target-grpc-smoke.sh > /path/outside/git/grpc-smoke.json` during the target run, then use `bash scripts/verify-target-release-evidence.sh --print-template > /path/outside/git/target-release-evidence.json` to create the external manifest skeleton. Fill it with concrete release artifact references, including the strict commercial verifier log artifact, the gRPC smoke artifact ID, and the `grpcSmokeReport.results` copied from the smoke JSON, then use `OBLIVIOUS_TARGET_EVIDENCE_FILE=/path/outside/git/target-release-evidence.json bash scripts/verify-target-release-evidence.sh` to validate live provider rails, deployed gRPC reachability, target secret audit, failover, and workflow telemetry before claiming final readiness. The manifest environment `name`, `class`, and `baseUrl` must be concrete target values, not TODO/example/sample placeholders, and `baseUrl` must be an HTTP(S) URL that does not point at localhost or another loopback target. The manifest must include `providers[]`, `grpc[]`, and an `artifacts[]` index whose entries have concrete `id`, `kind`, `uri`, and ISO-8601 `recordedAt` values; Agent/Workflow/Task `grpc[].address` and copied `grpcSmokeReport.results[].address` values must use non-local target service endpoints on the expected ports; artifact URIs must be remote target artifact URIs, not local filesystem paths, loopback URLs, or `file:` URLs; artifact URIs must not carry secret-like query or fragment parameters; artifact kind must match the referencing evidence family; optional `sha256` values must be 64-character hex digests; every non-placeholder `evidenceRef` must resolve to an `artifacts[].id`; every artifact id must be referenced by at least one `evidenceRef`; and duplicate artifact ids are rejected. The manifest's `workflowTelemetry.window` must be an ISO-8601 `start/end` interval whose end is at or after start. The manifest's `strictVerifier.command` must include `COMMERCIAL_COMPLETION_RUN_DEPLOY=true`, `COMMERCIAL_COMPLETION_RUN_K8S=true`, `COMMERCIAL_COMPLETION_RUN_BACKUP_RESTORE=true`, and `COMMERCIAL_COMPLETION_RUN_TARGET_EVIDENCE=true` on the strict commercial verifier command, and `strictVerifier.startedAt` / `completedAt` must bound the referenced run log.

## Integration-Test Skip Semantics

`TEST_DATABASE_URL` is optional only for local server gates. When it is unset locally, `bash scripts/test.sh server` must print `Skipping server integration tests: TEST_DATABASE_URL not set.` and the release evidence must record that DB-backed integration tests were skipped intentionally. When it is set, the server gate runs all packages serially to avoid shared test schema resets racing across Go packages.

CI server gates set `OBLIVIOUS_REQUIRE_TEST_DATABASE=true`. With that flag, missing `TEST_DATABASE_URL` is a failure and must print `TEST_DATABASE_URL is required when OBLIVIOUS_REQUIRE_TEST_DATABASE=true.`

When `TEST_DATABASE_URL` is set, the evidence must include the exact value class, not the secret value. Acceptable examples:

- `TEST_DATABASE_URL` pointed at disposable local Postgres.
- `TEST_DATABASE_URL` pointed at CI service Postgres.
- `TEST_DATABASE_URL` omitted in a local run; integration tests skipped by explicit rule.

## Deployment Preconditions

- Use only environment variable names and placeholders in committed config.
- If Docker daemon access, Docker registry/proxy access, or Kubernetes tooling is unavailable, follow [`deployment-runtime-remediation.md`](deployment-runtime-remediation.md) before recording DEPLOY-01 evidence.
- Copy `deploy/kubernetes/secret.example.yaml` to an untracked secret manifest before real cluster use.
- For local Docker smoke, run `bash scripts/deploy-validate.sh`. The script runs `docker compose config`, `docker compose build`, bounded `docker compose up -d` calls, `/usr/local/bin/oblivious-migrate`, then `BASE_URL=http://127.0.0.1:8080 bash scripts/deploy-smoke.sh`. Set `KEEP_STACK=true` to leave the compose stack running after validation, and tune `DEPLOY_VALIDATE_DOCKER_UP_TIMEOUT_SECONDS` only when a slow mirror is still making progress.
- If Docker Hub or `proxy.golang.org` is unreliable, use the validated restricted-network form: `OBLIVIOUS_IMAGE_REGISTRY_PREFIX=docker.m.daocloud.io/library/ OBLIVIOUS_POSTGRES_IMAGE=docker.m.daocloud.io/pgvector/pgvector:pg16 OBLIVIOUS_GOPROXY=https://mirrors.aliyun.com/goproxy/,direct OBLIVIOUS_GOSUMDB=sum.golang.google.cn bash scripts/deploy-validate.sh`.
- If pgvector image pulls are blocked, build the local fallback image with `docker build -f Dockerfile.postgres-pgvector -t oblivious-postgres-pgvector:pg16 .`, then run `OBLIVIOUS_POSTGRES_IMAGE=oblivious-postgres-pgvector:pg16 bash scripts/deploy-validate.sh`.
- For PostgreSQL recovery smoke, run `OBLIVIOUS_POSTGRES_IMAGE=oblivious-postgres-pgvector:pg16 bash scripts/backup-restore-smoke.sh`. See [`backup-restore-runbook.md`](backup-restore-runbook.md) for backup, restore, retention, encryption, and evidence rules.
- For OPS-04/OPS-05 observability evidence, review [`observability-slos.md`](observability-slos.md), `deploy/observability/prometheus-alerts.yaml`, and `deploy/observability/grafana-dashboard.json`, then run `node scripts/verify-observability-dashboard.mjs`. The Grafana dashboard artifact should include usage analytics dashboard coverage for model usage, feature usage, user cost, time trend, cross-dimension usage/cost analytics, and workflow active execution health. These artifacts prove repository-local metrics, alert, dashboard, and SLO coverage; external Prometheus/Grafana/OTel/error-tracking deployment and live dashboard rendering remain environment-specific evidence.
- For OPS-06/DOC-06 operations closeout evidence, review [`release-rollback-runbook.md`](release-rollback-runbook.md), [`incident-response-runbook.md`](incident-response-runbook.md), [`disaster-recovery-runbook.md`](disaster-recovery-runbook.md), and [`v07-operations-evidence.md`](v07-operations-evidence.md). Phase 24 verification records exact commands, skipped checks, residual v08 work, and the no-final-readiness boundary.
- For Kubernetes smoke, prepare the images referenced by the release manifests, fill the secret from `deploy/kubernetes/secret.example.yaml`, then run `OBLIVIOUS_K8S_SECRET_FILE=/path/outside/git/secret.yaml bash scripts/k8s-validate.sh`. The scripted release allowlist applies `namespace.yaml`, `network-policy.yaml`, the filled external Secret, `configmap.yaml`, `postgres.yaml`, `redis.yaml`, `qdrant.yaml`, `app-deployment.yaml`, `app-service.yaml`, `hpa.yaml`, and `ingress.yaml`; other microservice manifests are static/reference contracts until explicitly added to the target smoke. The docs gate also statically verifies the NetworkPolicy shape and first-party workload pod/container security contexts.
- For final commercial readiness, first run `AGENT_GRPC_ADDR=... WORKFLOW_GRPC_ADDR=... TASK_GRPC_ADDR=... bash scripts/target-grpc-smoke.sh > /path/outside/git/grpc-smoke.json` against the target Agent/Workflow/Task gRPC endpoints. Then generate the target evidence JSON outside git with `bash scripts/verify-target-release-evidence.sh --print-template > /path/outside/git/target-release-evidence.json`, replace every `TODO` value with concrete target-run artifact references, record the strict verifier log artifact and start/end timestamps, copy the gRPC smoke JSON into `grpcSmokeReport`, fill the `artifacts[]` index with the concrete logs/CI runs/provider records/dashboard exports referenced by each `evidenceRef`, and validate it with `OBLIVIOUS_TARGET_EVIDENCE_FILE=/path/outside/git/target-release-evidence.json bash scripts/verify-target-release-evidence.sh`. The manifest must point to logs/artifacts rather than embedding secrets, the unfilled template is intentionally rejected by the verifier, every `evidenceRef` must resolve to an artifact id in `artifacts[]`, artifact ids must be unique and referenced, `workflowTelemetry.window` must be a valid ISO-8601 `start/end` interval, `grpcSmokeReport.results` must match the `grpc` addresses and pass statuses for Agent, Workflow, and Task, and `strictVerifier.command` must carry all four final gate flags: deploy, Kubernetes, backup/restore, and target evidence.
- Do not commit provider keys, Stripe secrets, database passwords, session secrets, kubeconfig material, or signed artifact URLs with token/signature/API-key query parameters.
- The deployment smoke target must expose `/healthz` before the release can be called healthy.
