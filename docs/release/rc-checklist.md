# RC Checklist

This checklist is the minimum release-candidate gate for the current Oblivious mainline. It covers only `src/server`, `src/web`, `config`, `scripts`, `.github/workflows`, and release docs. `lobehub/` and `new-api/` remain reference trees.

Commercial readiness is a stricter gate than RC readiness. Use [`commercial-gates.md`](commercial-gates.md) before claiming commercial readiness or commercial completeness.

No live provider keys are required for local or CI docs checks, web tests, server tests, or fixture-backed Admin/Marketplace E2E. Use placeholder environment values unless a deployment smoke target explicitly needs real infrastructure. Final commercial readiness still requires target provider live-rail evidence for Stripe, Alipay, and WeChat Pay.

Commercial-readiness renewal additionally requires target/live evidence. Use `AGENT_GRPC_ADDR=... WORKFLOW_GRPC_ADDR=... TASK_GRPC_ADDR=... bash scripts/target-grpc-smoke.sh > /path/outside/git/grpc-smoke.json` during the target run, export concrete `OBLIVIOUS_TARGET_*` environment values for the target environment, strict verifier timestamps, workflow telemetry, every release artifact URI, and every matching artifact SHA-256 digest, then run `bash scripts/assemble-target-release-evidence.sh --grpc-smoke-file /path/outside/git/grpc-smoke.json --strict-verifier-proof-file /path/outside/git/strict-verifier.json --deployment-proof-file /path/outside/git/deployment-proof.json --kubernetes-proof-file /path/outside/git/kubernetes-proof.json --stripe-provider-live-rail-proof-file /path/outside/git/stripe-provider-live-rail.json --alipay-provider-live-rail-proof-file /path/outside/git/alipay-provider-live-rail.json --wechatpay-provider-live-rail-proof-file /path/outside/git/wechatpay-provider-live-rail.json --secret-audit-proof-file /path/outside/git/secret-audit.json --workflow-telemetry-proof-file /path/outside/git/workflow-telemetry.json --request-log-platform-proof-file /path/outside/git/clickhouse-request-log-platform-proof.json --request-log-coverage-file /path/outside/git/usage-request-log-coverage.json --request-log-slo-file /path/outside/git/latency-slo-proof.json --rag-proof-file /path/outside/git/rag-indexing-proof.json --relay-realtime-proof-file /path/outside/git/relay-realtime-proof.json --relay-batch-proof-file /path/outside/git/relay-batch-proof.json --marketplace-payout-proof-file /path/outside/git/marketplace-payout-proof.json --marketplace-governance-proof-file /path/outside/git/marketplace-governance-proof.json --provider-runtime-config-proof-file /path/outside/git/provider-runtime-config-proof.json --microservice-database-proof-file /path/outside/git/microservice-database-proof.json --output /path/outside/git/target-release-evidence.json --validate`. The assembler does not create evidence and does not relax the strict verifier; it only assembles already-collected target artifact URIs, timestamps, telemetry, artifact digests, strict verifier, deployment, Kubernetes, provider live rail, secret audit, workflow telemetry, request-log, RAG, Relay, Marketplace, provider runtime config, and microservice database raw proof files, and the gRPC smoke JSON into the manifest and calls `verify-target-release-evidence.sh` when `--validate` is set. `bash scripts/verify-target-release-evidence.sh --print-template` remains available for schema inspection or emergency manual assembly, but the preferred release flow is the assembler plus strict validation. Final commercial readiness must set `OBLIVIOUS_TARGET_ARTIFACT_DIR=/path/outside/git/downloaded-artifacts`; each `<artifact-id>.json` body is checked against the manifest SHA-256, lineage metadata, provider metadata, and required deployment, Kubernetes, provider live rail, request-log observability, RAG indexing, Relay lifecycle, Marketplace payout/governance, provider runtime config, and microservice database proof fields. Request-log observability bodies must carry both `collectionSource` for usage/request-log coverage and `platformProofSource` for ClickHouse deployment, migration, table, and ingest/query smoke proof. The manifest environment `name`, `class`, and `baseUrl` must be concrete target values, not TODO/example/sample/fake placeholders; `environment.class` must be exactly `staging`, `preproduction`, or `production`; and `baseUrl` must be an HTTP(S) URL that does not point at localhost, another loopback target, abbreviated/octal/hex IPv4 loopback such as `127.1`, `0177.0.0.1`, or `0x7f.0.0.1`, a wildcard target such as host `0`, or a reserved `.invalid` host, does not embed URI userinfo credentials, and does not carry secret-like query or fragment parameters such as `token`, `token=`, `password`, or `password=`. The manifest must include `providers[]`, `grpc[]`, `kubernetes.secretFileClass=external-filled`, and an `artifacts[]` index whose entries have concrete `id`, `kind`, `uri`, required 64-character hex `sha256`, and ISO-8601 `recordedAt` values; Agent/Workflow/Task `grpc[].address` and copied `grpcSmokeReport.results[].address` values must use plain `host:port` or `[ipv6]:port` non-local target service endpoints on the expected ports, not URL-shaped, abbreviated/octal/hex loopback, reserved `.invalid`, fake, or wildcard values such as `https://host:port`, `127.1:50063`, `0177.0.0.1:50063`, `0x7f.0.0.1:50063`, `target.invalid:50063`, or `0:50063`; `grpcSmokeReport.timeout` must be a positive Go duration string such as `10s`; artifact URIs must be remote target artifact URIs with an authority/host, not local filesystem paths, loopback URLs, abbreviated/octal/hex IPv4 loopback URLs, reserved `.invalid` URLs, wildcard `0` URLs, `file:` URLs, or inline schemes such as `data:`; artifact URIs must not carry secret-like query or fragment parameters such as `token`, `token=`, `password`, or `password=`; the manifest itself must not include secret-like fields such as tokens or API keys under `secretAudit`, and `secretAudit.scope` must include `kubernetes`, `providers`, and `runtime`; artifact kind must match the referencing evidence family; `provider-live-rail` artifacts must carry `provider` metadata matching the referencing Stripe, Alipay, or WeChat Pay row; `deployment-log`, `kubernetes-validation`, `provider-live-rail`, `request-log-observability`, `rag-indexing-proof`, `relay-realtime-proof`, `relay-batch-proof`, `marketplace-payout-proof`, `marketplace-governance-proof`, `provider-runtime-config`, and `microservice-database-proof` artifacts must also carry artifact-level `proofs` metadata that repeats the required deployment, Kubernetes, provider live rail, request-log, RAG indexing, Relay lifecycle, payout/governance, provider runtime config, and microservice database proof keys as `pass`; every artifact `sha256` value must be present and must be a 64-character hex digest; every non-placeholder `evidenceRef` must resolve to an `artifacts[].id`; every artifact id must be referenced by at least one `evidenceRef`; and duplicate artifact ids are rejected. The manifest's `workflowTelemetry.successRate` must be between `0.99` and `1.0`, and `workflowTelemetry.window` must be an ISO-8601 `start/end` interval whose end is at or after start. The manifest's `strictVerifier.command` must include `COMMERCIAL_COMPLETION_RUN_DEPLOY=true`, `COMMERCIAL_COMPLETION_RUN_K8S=true`, `COMMERCIAL_COMPLETION_RUN_BACKUP_RESTORE=true`, and `COMMERCIAL_COMPLETION_RUN_TARGET_EVIDENCE=true` on the strict commercial verifier command, must not set `OBLIVIOUS_TARGET_EVIDENCE_ALLOW_COMMIT_MISMATCH=true`, and `strictVerifier.startedAt` / `completedAt` must bound the referenced run log.

IPv6 unspecified, abbreviated IPv4 loopback, and short wildcard environment base URLs such as `http://[::]:3000`, `http://127.1:3000`, and `http://0:3000` are treated as local/non-target values and are rejected for the same reason as loopback and wildcard bind addresses.

Target provider live-rail evidence is limited to Stripe, Alipay, and WeChat Pay checkout/refund/payout/reconciliation rows. Extra manifest providers such as `paypal` are rejected instead of being treated as supplemental evidence.

Target gRPC evidence is limited to validation-only Agent, Workflow, and Task generated-client smoke results. Extra manifest or copied smoke-result services such as `admin:50066` are rejected instead of being treated as harmless notes.

Target evidence also requires structured `requestLogObservability`, `ragIndexing`, `relayRealtime`, `relayBatch`, `marketplacePayouts`, `marketplaceGovernance`, `providerRuntimeConfig`, and `microserviceDatabases` sections. They must prove ClickHouse request-log deployment, ClickHouse migration, `request_logs` ingest/query smoke, request-log to usage/billing joins by `request_id`, durable RAG index queue migration, RAG worker rollout, enqueue/drain, raw parser replay, Realtime production-disabled policy plus explicit auth/origin/prebill/abort/usage blockers, Batch production-disabled policy plus explicit prebill/polling/settlement/refund/audit/usage-capture blockers, retrieval probes, marketplace payout outbound dispatch plus inbound webhook lifecycle, settlement ledger, reconciliation, refund/chargeback handling, Marketplace review queue, appeal queue, appeal decision lifecycle, review assignment, review SLA enforcement, abuse-report lifecycle, Stripe/Alipay/WeChat Pay runtime provider configuration, and external-filled microservice database URLs in `microservices` mode for Relay, Chat, Workflow, RAG, Agent, Billing, Marketplace, Admin, Channel, Task, and Observability. Each section must resolve through `artifacts[]` to the matching artifact kind: `request-log-observability`, `rag-indexing-proof`, `relay-realtime-proof`, `relay-batch-proof`, `marketplace-payout-proof`, `marketplace-governance-proof`, `provider-runtime-config`, or `microservice-database-proof`. The `deployment-log` artifact must include `proofs.deployValidation`, `proofs.backupRestore`, and `proofs.migrationReplay` as `pass`; the `kubernetes-validation` artifact must include `proofs.validation`, `proofs.rollout`, and `proofs.failover` as `pass`; each `provider-live-rail` artifact must include `proofs.checkout`, `proofs.refund`, `proofs.payout`, and `proofs.reconciliation` as `pass`; the `request-log-observability` artifact must include `proofs.clickHouseDeployment`, `proofs.clickHouseMigration`, `proofs.requestLogsTable`, `proofs.ingestQuerySmoke`, `proofs.requestUsageJoin`, `proofs.latencySLOTrigger`, `proofs.latencySLOAlertDelivery`, and `proofs.latencySLORecoveryAction` as `pass`, plus `platformProofSource` pointing to the ClickHouse platform proof collection source; the `relay-realtime-proof` artifact must include `proofs.productionPolicyDisabled` and `proofs.authOriginPrebillAbortUsageBlockers` as `pass`; the `relay-batch-proof` artifact must include `proofs.productionPolicyDisabled` and `proofs.prebillPollingSettlementRefundAuditUsageBlockers` as `pass`; the `marketplace-payout-proof` artifact must include `proofs.outboundDispatch`, `proofs.inboundWebhookLifecycle`, `proofs.settlementLedger`, `proofs.reconciliation`, and `proofs.refundChargebackHandling` as `pass`; the `marketplace-governance-proof` artifact must include `proofs.reviewQueue`, `proofs.appealQueue`, `proofs.appealDecisionLifecycle`, `proofs.reviewAssignment`, `proofs.reviewSLAEnforcement`, and `proofs.abuseReportLifecycle` as `pass`; the `provider-runtime-config` artifact must include `proofs.stripe`, `proofs.alipay`, `proofs.wechatpay`, `proofs.providerEnv`, `proofs.checkoutBaseUrls`, `proofs.webhookRoutes`, and `proofs.webhookVerification` as `pass`; the `microservice-database-proof` artifact must include service proofs including `proofs.agent` plus `proofs.migrationReadiness` as `pass`.

Final target evidence must not set `COMMERCIAL_COMPLETION_ALLOW_ENV_SKIPS=true` or `OBLIVIOUS_TARGET_EVIDENCE_ALLOW_COMMIT_MISMATCH=true` in `strictVerifier.command`, including shell-valid single-quoted or double-quoted `true` values. Any environment-skip or commit-mismatch run is local partial evidence only, not commercial-readiness proof.

Final commercial target evidence defaults to `environment.class=production`. `--allow-non-production-target` is only for staging or preproduction RC inspection and cannot support a full commercial release claim.

Final Relay evidence defaults to `relayRealtime.mode=commercial_lifecycle_enabled` and `relayBatch.mode=commercial_lifecycle_enabled`. `--allow-disabled-commercial-lifecycle` is only for legacy, negative, or excluded-surface inspection; disabled Relay lifecycle evidence is not a complete commercial release claim.

Strict verifier proof JSON must carry `commit`, `runId`, `targetEvidenceSha256`, and `artifactBundleSha256`. After collecting artifact bodies, run `bash scripts/compute-target-release-digests.sh --manifest /path/outside/git/oblivious-release/target-release-evidence.json --artifact-dir /path/outside/git/oblivious-release/artifacts --write` or `npm run verify:target-release:digests -- --manifest /path/outside/git/oblivious-release/target-release-evidence.json --artifact-dir /path/outside/git/oblivious-release/artifacts --write` to compute the canonical normalized manifest and artifact-bundle digests, refresh the manifest, and refresh the strict-verifier artifact body. When `OBLIVIOUS_TARGET_ARTIFACT_DIR` is supplied, the verifier recomputes those canonical digest values and rejects hand-filled or stale strict verifier digest fields, then checks that the strict-verifier proof body repeats the manifest digest fields, so a strict-verifier log from a different release run cannot be reused as final proof.

## Final Commercial Release Runbook

Use one release working directory outside git, for example `/path/outside/git/oblivious-release`, with separate `raw/`, `artifacts/`, and `logs/` subdirectories. The final release claim is the last strict verifier run after every artifact body has been collected and the target manifest SHA-256 values have been refreshed.

The strict preflight rejects `OBLIVIOUS_TARGET_EVIDENCE_FILE` and `OBLIVIOUS_TARGET_ARTIFACT_DIR` when they point inside the repository. Final release evidence must be external, untracked target output, not a checked-in fixture or local workspace artifact.

1. Collect raw target proof. Run `AGENT_GRPC_ADDR=agent.target.example.com:50063 WORKFLOW_GRPC_ADDR=workflow.target.example.com:50064 TASK_GRPC_ADDR=task.target.example.com:50065 bash scripts/target-grpc-smoke.sh > /path/outside/git/oblivious-release/raw/grpc-smoke.json`, export or fetch the protected target proof JSON for strict verifier, deployment, Kubernetes, workflow telemetry, secret audit, request-log coverage, ClickHouse request-log platform readiness, RAG indexing, Relay Realtime, Relay Batch, Marketplace payout, Marketplace governance, provider runtime config, Stripe/Alipay/WeChat Pay live rails, and microservice databases, and store all raw proof outside git.
2. Run the strict commercial verifier once with all final gates enabled and save its command, start/end timestamps, result, and skipped-check list to the strict-verifier raw proof. This run must use `TEST_DATABASE_URL`, `OBLIVIOUS_K8S_SECRET_FILE`, `OBLIVIOUS_TARGET_EVIDENCE_FILE`, and `OBLIVIOUS_TARGET_ARTIFACT_DIR`, must set `COMMERCIAL_COMPLETION_RUN_DEPLOY=true`, `COMMERCIAL_COMPLETION_RUN_K8S=true`, `COMMERCIAL_COMPLETION_RUN_BACKUP_RESTORE=true`, and `COMMERCIAL_COMPLETION_RUN_TARGET_EVIDENCE=true`, and must not set `COMMERCIAL_COMPLETION_ALLOW_ENV_SKIPS=true`. Missing final gate flags, a missing strict final input bundle, or an invalid Kubernetes secret file fail before the expensive docs, web, Go, DB, deploy, Kubernetes, backup, and target evidence checks begin.
3. Assemble the manifest with `bash scripts/assemble-target-release-evidence.sh --grpc-smoke-file /path/outside/git/oblivious-release/raw/grpc-smoke.json --strict-verifier-proof-file /path/outside/git/oblivious-release/raw/strict-verifier.json --deployment-proof-file /path/outside/git/oblivious-release/raw/deployment-proof.json --kubernetes-proof-file /path/outside/git/oblivious-release/raw/kubernetes-proof.json --stripe-provider-live-rail-proof-file /path/outside/git/oblivious-release/raw/stripe-provider-live-rail.json --alipay-provider-live-rail-proof-file /path/outside/git/oblivious-release/raw/alipay-provider-live-rail.json --wechatpay-provider-live-rail-proof-file /path/outside/git/oblivious-release/raw/wechatpay-provider-live-rail.json --secret-audit-proof-file /path/outside/git/oblivious-release/raw/secret-audit.json --workflow-telemetry-proof-file /path/outside/git/oblivious-release/raw/workflow-telemetry.json --request-log-platform-proof-file /path/outside/git/oblivious-release/raw/clickhouse-request-log-platform-proof.json --request-log-coverage-file /path/outside/git/oblivious-release/raw/usage-request-log-coverage.json --request-log-slo-file /path/outside/git/oblivious-release/raw/latency-slo-proof.json --rag-proof-file /path/outside/git/oblivious-release/raw/rag-indexing-proof.json --relay-realtime-proof-file /path/outside/git/oblivious-release/raw/relay-realtime-proof.json --relay-batch-proof-file /path/outside/git/oblivious-release/raw/relay-batch-proof.json --marketplace-payout-proof-file /path/outside/git/oblivious-release/raw/marketplace-payout-proof.json --marketplace-governance-proof-file /path/outside/git/oblivious-release/raw/marketplace-governance-proof.json --provider-runtime-config-proof-file /path/outside/git/oblivious-release/raw/provider-runtime-config-proof.json --microservice-database-proof-file /path/outside/git/oblivious-release/raw/microservice-database-proof.json --output /path/outside/git/oblivious-release/target-release-evidence.json --validate`. The assembler creates the manifest shape and evidence refs from already-collected target proof; it does not collect proof bodies.
4. Collect and hash every artifact body with the aggregate collector. For final evidence, prefer protected HTTPS target URLs or target Admin APIs so each body records `collectionSource.type=target-url` or `collectionSource.type=target-api`:

```bash

  --manifest /path/outside/git/oblivious-release/target-release-evidence.json \

  --strict-verifier-url https://target.example.com/internal/release/strict-verifier.json \

  --kubernetes-proof-url https://target.example.com/internal/release/kubernetes-proof.json \

  --request-log-platform-proof-url https://target.example.com/internal/release/clickhouse-request-log-platform-proof.json \
  --target-base-url https://target.example.com \

  --relay-realtime-proof-url https://target.example.com/api/v1/admin/release-evidence/relay-realtime \

  --alipay-provider-live-rail-url https://target.example.com/internal/release/alipay-provider-live-rail.json \
  --wechatpay-provider-live-rail-url https://target.example.com/internal/release/wechatpay-provider-live-rail.json \
  --grpc-smoke-url https://target.example.com/internal/release/grpc-smoke.json \
  --secret-audit-url https://target.example.com/internal/release/secret-audit.json \
  --microservice-database-proof-url https://target.example.com/api/v1/admin/release-evidence/microservice-database
```

5. Compute canonical digest fields and refresh the manifest plus strict-verifier artifact body:

```bash
bash scripts/compute-target-release-digests.sh \
  --manifest /path/outside/git/oblivious-release/target-release-evidence.json \
  --artifact-dir /path/outside/git/oblivious-release/artifacts \
  --write \
  --output /path/outside/git/oblivious-release/target-release-digests.json
```

6. Revalidate the refreshed manifest and downloaded artifact bodies with `OBLIVIOUS_TARGET_ARTIFACT_DIR=/path/outside/git/oblivious-release/artifacts bash scripts/verify-target-release-evidence.sh /path/outside/git/oblivious-release/target-release-evidence.json`.
7. Run the target evidence preflight before the expensive final verifier path with `COMMERCIAL_COMPLETION_RUN_TARGET_EVIDENCE=true OBLIVIOUS_TARGET_EVIDENCE_FILE=/path/outside/git/oblivious-release/target-release-evidence.json OBLIVIOUS_TARGET_ARTIFACT_DIR=/path/outside/git/oblivious-release/artifacts node scripts/verify-commercial-preflight.mjs --target-evidence-only`; the strict completion verifier runs the same preflight automatically when target evidence is enabled.
8. Run the final commercial verifier with no skip flags and attach the terminal log as the release decision evidence:

```bash
TEST_DATABASE_URL=postgres://... \
OBLIVIOUS_K8S_SECRET_FILE=/path/outside/git/secret.yaml \
OBLIVIOUS_TARGET_EVIDENCE_FILE=/path/outside/git/oblivious-release/target-release-evidence.json \
OBLIVIOUS_TARGET_ARTIFACT_DIR=/path/outside/git/oblivious-release/artifacts \
COMMERCIAL_COMPLETION_RUN_DEPLOY=true \
COMMERCIAL_COMPLETION_RUN_K8S=true \
COMMERCIAL_COMPLETION_RUN_BACKUP_RESTORE=true \
COMMERCIAL_COMPLETION_RUN_TARGET_EVIDENCE=true \
bash scripts/verify-commercial-completion.sh
```

The strict-verifier artifact in the refreshed manifest may reference the immediately preceding no-skip strict verifier pass for the same commit and command shape. The publishable readiness claim is the final rerun above, where that artifact body, every target proof body, and the manifest all validate together.

## Integration-Test Skip Semantics

`TEST_DATABASE_URL` is optional only for local server gates. When it is unset locally, `bash scripts/test.sh server` must print `Skipping server integration tests: TEST_DATABASE_URL not set.` and the release evidence must record that DB-backed integration tests were skipped intentionally. When it is set, the server gate runs all packages serially to avoid shared test schema resets racing across Go packages.

CI server gates set `OBLIVIOUS_REQUIRE_TEST_DATABASE=true`. With that flag, missing `TEST_DATABASE_URL` is a failure and must print `TEST_DATABASE_URL is required when OBLIVIOUS_REQUIRE_TEST_DATABASE=true.`

When `TEST_DATABASE_URL` is set, the evidence must include the exact value class, not the secret value. Acceptable examples:

- `TEST_DATABASE_URL` pointed at disposable local Postgres.
- `TEST_DATABASE_URL` pointed at CI service Postgres.
- `TEST_DATABASE_URL` omitted in a local run; integration tests skipped by explicit rule.
