## 2024-06-25 - SQL Injection in migration toolkit
**Vulnerability:** SQL injection vulnerability in `src/server/internal/migration/validator.go` and `src/server/internal/migration/secret_storage_audit.go`. User input (table names and column names) are passed directly into a raw SQL query using `fmt.Sprintf` in `ValidateTableRowCount`, `ValidateTableChecksum`, `auditScalarSecretRows`, and `auditJSONSecretRows`.
**Learning:** Migration tools and database verifiers sometimes dynamically construct SQL queries with table and column names that cannot be parameterized using standard driver variables (like `$1`). These identifiers must be double-quoted to prevent SQL injection when the identifiers are provided by external input, such as migration configurations or API payloads.
**Prevention:** Always quote database identifiers (tables, columns) manually in Go (e.g. `"` + strings.ReplaceAll(ident, `"`, `""`) + `"`) if they must be constructed dynamically, and update test cases to expect the quoted identifiers.
