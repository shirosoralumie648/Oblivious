```go
type ChannelStore interface {
    ListChannels(ctx context.Context, filter ChannelFilter) ([]*ChannelInfo, error)
    GetChannel(ctx context.Context, id string) (*ChannelInfo, error)
    CreateChannel(ctx context.Context, input ChannelCreateRequest) (*ChannelInfo, error)

    DeleteChannel(ctx context.Context, id string) error
    TestChannel(ctx context.Context, id string) (*ChannelTestResult, error)
    BatchUpdateChannels(ctx context.Context, ids []string, action string) error
}
```
2. Create `ChannelFilter` type: `type ChannelFilter struct { Provider string; Status string; Search string; Limit int; Offset int }`
3. Implement SQLStore methods on the channels table:
   - `ListChannels`: SELECT from channels with optional WHERE provider/name LIKE filters, ORDER BY created_at DESC, LIMIT/OFFSET
   - `GetChannel`: SELECT by id
   - `CreateChannel`: INSERT with uuid generation (use `auth.NewID("ch")` from auth package), encrypt API key (plain text for now — env-based), return ChannelInfo
   - `UpdateChannel`: UPDATE with NULLIF for optional pointer fields, UPDATE updated_at = NOW()
   - `DeleteChannel`: DELETE by id
   - `BatchUpdateChannels`: UPDATE channels SET enabled = (action="enable") WHERE id = ANY($1)
   - `TestChannel`: Look up channel config, make a lightweight HTTP GET to channel's base_url + "/models" with API key header. Return latency in ms. If error, return ChannelTestResult{Success: false, Error: err.Error()}. Timeout: 5 seconds.
4. All methods use parameterized queries (`$1`, `$2`, etc.)
5. Error wrapping: `fmt.Errorf("list channels: %w", err)`

Create `src/server/internal/admin/route_store.go`:

1. Define `RouteStore` interface:
```go
type RouteStore interface {
    ListRoutes(ctx context.Context) ([]*RouteInfo, error)
    GetRoute(ctx context.Context, id string) (*RouteInfo, error)
    CreateRoute(ctx context.Context, input RouteCreateRequest) (*RouteInfo, error)
    UpdateRoute(ctx context.Context, id string, input RouteUpdateRequest) (*RouteInfo, error)
    DeleteRoute(ctx context.Context, id string) error
}
```
2. SQLStore methods:
   - `ListRoutes`: SELECT r.*, array_agg of channel weights with channel name. JOIN model_routes r LEFT JOIN model_channel_weights w ON r.id = w.route_id LEFT JOIN channels c ON w.channel_id = c.id. GROUP BY r.id.
   - `GetRoute`: Same as ListRoutes but WHERE r.id = $1
   - `CreateRoute`: BEGIN TXN. INSERT INTO model_routes (id, model, strategy). For each channel in input.Channels: INSERT INTO model_channel_weights. COMMIT. Return full route with channels.
   - `UpdateRoute`: BEGIN TXN. UPDATE model_routes SET ... WHERE id = $1. DELETE FROM model_channel_weights WHERE route_id = $1. INSERT new weights. COMMIT.
   - `DeleteRoute`: DELETE FROM model_routes WHERE id = $1 (CASCADE deletes weights)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Channel API key storage | api_key_encrypted stored in DB — encryption handled at the relay layer, admin service passes through |
| Audit log appends | audit_logs is append-only — no UPDATE/DELETE exposed by admin service |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Spoofing | channel_service.CreateChannel | mitigate | Actor identity comes from authenticated session (Plan 06 middleware). Service validates non-empty actor ID before audit. |
| T-03-06 | Tampering | audit_store.CreateAuditEntry | mitigate | Audit entries are immutable once written. No Update/Delete methods on AuditStore. Changes JSON is a snapshot at write time. |
| T-03-07 | Information Disclosure | channel TestChannel | mitigate | Test connection result (latency, error) is admin-only. No API keys returned in response. |
| T-03-08 | Denial of Service | BatchUpdateChannels | mitigate | Batch operations limited to 100 IDs max. Use single UPDATE with WHERE id = ANY($1) to avoid N+1 queries. |
</threat_model>
