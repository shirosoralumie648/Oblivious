```go
type UserStore interface {

}
```
Note: `ListUsers` now returns `([]*UserDetail, int, error)` — including total count for pagination.

2. Implement SQLStore methods:

**ListUsers(ctx, filter UserListFilter) ([]*UserDetail, int, error)** per D-12 (search, filter, sort, paginate):
   - Build query dynamically using `strings.Builder` for WHERE clause construction.
   - Base SELECT:
     ```sql
     SELECT u.id, u.email, u.name, u.role, u.plan_id, p.name AS plan_name, u.status,
            u.created_at, u.last_login_at,
            COALESCE(SUM(ur.tokens_used), 0) AS total_tokens,
            COALESCE(SUM(ur.api_calls), 0) AS total_api_calls,
            COALESCE(SUM(ur.cost), 0) AS total_cost
     FROM users u
     LEFT JOIN packages p ON u.plan_id = p.id
     LEFT JOIN usage_records ur ON u.id = ur.user_id
     ```
   - WHERE clause construction (applied with parameterized $N placeholders):
     - `filter.Search != ""`: `AND (u.name ILIKE '%' || $n || '%' OR u.email ILIKE '%' || $n || '%')`
     - `filter.Role != ""`: `AND u.role = $n`
     - `filter.PlanID != ""`: `AND u.plan_id = $n`
     - `filter.Status != ""`: `AND u.status = $n`
   - GROUP BY: `GROUP BY u.id, p.name`
   - Sort (per D-12 — multi-sort support):
     - `filter.Sort == ""` or `"created_at_desc"`: `ORDER BY u.created_at DESC`
     - `"created_at_asc"`: `ORDER BY u.created_at ASC`
     - `"name_asc"`: `ORDER BY u.name ASC`
     - `"name_desc"`: `ORDER BY u.name DESC`
     - `"tokens_desc"`: `ORDER BY total_tokens DESC`
     - `"last_login_desc"`: `ORDER BY u.last_login_at DESC NULLS LAST`
   - LIMIT/OFFSET: `LIMIT $n OFFSET $n` (clamp limit between 1 and 100)

   - Run a separate COUNT query (same WHERE, no JOINs/GROUP BY) to get total. `SELECT COUNT(*) FROM users u WHERE ...`
   - Return the list and total count. If rows returned but no usage records, total_tokens/total_api_calls/total_cost default to 0 via COALESCE.

**GetUserByID(ctx, id string) (*UserDetail, error)** per D-13 (usage stats in detail view):
   - Same JOIN query as ListUsers but WHERE u.id = $1.
   - Also aggregate usage by current billing period: add subquery for `SUM(ur.tokens_used) FILTER (WHERE ur.recorded_at >= CURRENT_DATE - INTERVAL '30 days') AS tokens_this_period`.
   - Return *UserDetail with UsageStats populated. If user not found, return `sql.ErrNoRows`.

**UpdateUser(ctx, id string, input UserUpdateRequest) (*UserDetail, error)** per D-16 (RBAC role assignment + plan assignment):
   - UPDATE users SET
     - `role = COALESCE(NULLIF($1, ''), role)` — only admin/moderator/user allowed (D-16: predefined roles only)
     - `plan_id = COALESCE($2, plan_id)` — if plan_id changes, also update subscriptions table for active subscription
     - `status = COALESCE(NULLIF($3, ''), status)` — status changes handled separately via DisableUser/EnableUser
   - WHERE id = $4
   - RETURNING the updated UserDetail (re-run the GetUserByID join query)
   - If plan_id is updated and user has an active subscription: UPDATE subscriptions SET package_id = $new_plan_id WHERE user_id = $id AND status = 'active'

**DisableUser(ctx, id string) error** per D-12 (full lifecycle):
   - BEGIN transaction.
   - UPDATE users SET status = 'disabled' WHERE id = $1. Return error if no rows affected (user not found).
   - DELETE FROM sessions WHERE user_id = $1 (revoke all active sessions — user immediately logged out everywhere).
   - COMMIT.
   - Return nil.

**EnableUser(ctx, id string) error** per D-12:
   - UPDATE users SET status = 'active' WHERE id = $1. Return error if no rows affected.
   - Does NOT recreate sessions — user must log in again.

**CountUsers(ctx, filter UserListFilter) (int, error)**:
   - SELECT COUNT(*) FROM users with same WHERE filters as ListUsers. Used for dashboard stats (D-07 total user count).

3. All queries use parameterized placeholders (`$1`, `$2`, etc.). Error wrapping: `fmt.Errorf("list users: %w", err)`.

4. Imports: `"database/sql"`, `"fmt"`, `"strings"`, `"context"`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin API caller | Only admin/moderator roles can access user management endpoints (enforced at handler layer in Plan 06). Service layer performs additional self-action guards. |
| User detail data | Usage stats aggregate across all usage_records — PII in email/name is admin-only |
| Session revocation | DisableUser deletes all sessions for the target user — cross-user impact validated by role check |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-15 | Elevation of Privilege | user_service UpdateUser | mitigate | Role change validates against predefined set {admin, moderator, user} per D-16. Self-role-change blocked (actorID == id check). RBAC enforcement at handler layer (Plan 06) is the primary gate. |
| T-03-16 | Elevation of Privilege | user_service DisableUser | mitigate | Cannot disable self. Actor identity from authenticated session. Audit log records actor_id on every disable. |
| T-03-17 | Denial of Service | user_service DisableUser | mitigate | Session deletion is DELETE FROM sessions WHERE user_id = $1 — single query, no N+1. Transaction ensures atomicity (status update + session deletion). |
| T-03-18 | Information Disclosure | user_store ListUsers | mitigate | Usage stats aggregation uses LEFT JOIN + COALESCE — no error if usage_records missing. Search supports partial match via ILIKE with parameterized query (SQL injection impossible). |
| T-03-19 | Repudiation | user_service (all mutations) | mitigate | Every mutation (update, disable, enable) writes audit_logs with actor_id, timestamp, IP, changes. Immutable audit trail. |
</threat_model>
