3. Implement SQLStore methods on the `packages` table:

   - **ListPlans**: SELECT from packages. WHERE clauses: `is_active = COALESCE(filter.IsActive, is_active)`, `is_public = COALESCE(filter.IsPublic, is_public)`, `name ILIKE '%' || $search || '%'` when filter.Search non-empty. ORDER BY sort_order ASC, created_at DESC. LIMIT/OFFSET. Returns `[]*PlanInfo`.

   - **GetPlan**: SELECT by id. Return `*PlanInfo` or `sql.ErrNoRows`.

   - **CreatePlan**: INSERT INTO packages with uuid generation (use `auth.NewID("pkg")`). Fields: name, description, quota_amount, token_quota, price, model_access (store as PostgreSQL TEXT[] via `pq.Array(input.ModelAccess)`), agent_limit, duration_days, is_public, sort_order. Set is_active = true. Set created_at = NOW(), updated_at = NOW(). Return the created PlanInfo with RETURNING clause. Per D-10: token_quota and price represent the hybrid pricing model (base monthly + per-token overage).

   - **UpdatePlan**: UPDATE packages SET ... WHERE id = $1. Use `COALESCE($n, column)` pattern for nullable pointer update fields: `name = COALESCE(NULLIF($1, ''), name)`, `description = COALESCE($2, description)`, `quota_amount = COALESCE($3, quota_amount)`, `token_quota = COALESCE($4, token_quota)`, `price = COALESCE($5, price)`, `model_access = COALESCE($6, model_access)`, `agent_limit = COALESCE($7, agent_limit)`, `is_active = COALESCE($8, is_active)`, `is_public = COALESCE($9, is_public)`. Always UPDATE updated_at = NOW(). Use RETURNING to get updated PlanInfo. Per D-11: plan form config fields are all updatable via this single endpoint.

   - **DeactivatePlan**: UPDATE packages SET is_active = false, updated_at = NOW() WHERE id = $1. Do NOT delete — subscriptions may reference this plan for historical billing. Return error if no rows affected.

4. All queries use parameterized placeholders ($1, $2, etc.). Error wrapping: `fmt.Errorf("list plans: %w", err)`.

5. Import `"github.com/lib/pq"` for `pq.Array()` on PostgreSQL TEXT[] columns. Import `"database/sql"` for `sql.ErrNoRows`.

```go
type CheckoutConfig struct {
    SecretKey      string // STRIPE_SECRET_KEY env var
    SuccessURL     string // Frontend success redirect URL
    CancelURL      string // Frontend cancel redirect URL
    WebhookSecret  string // STRIPE_WEBHOOK_SECRET env var
}
```

2. Function `CreateCheckoutSession(ctx context.Context, cfg CheckoutConfig, req CheckoutSessionRequest) (*stripe.CheckoutSession, error)`:
   - Set `stripe.Key = cfg.SecretKey`
   - Look up plan from admin PlanStore to get price and name
   - Create a `stripe.CheckoutSessionParams`:
     - `PaymentMethodTypes`: `[]*string{stripe.String("card")}`
     - `Mode`: `stripe.String(string(stripe.CheckoutSessionModeSubscription))` for recurring plans, `stripe.String(string(stripe.CheckoutSessionModePayment))` for one-time
     - `LineItems`: one line item with `PriceData`:
       - `Currency`: `"usd"`
       - `ProductData.Name`: plan name
       - `UnitAmount`: `int64(plan.Price * 100)` (Stripe uses cents)
       - `Recurring`: set only if plan has DurationDays (monthly subscription)
     - `SuccessURL`: `cfg.SuccessURL + "?session_id={CHECKOUT_SESSION_ID}"`
     - `CancelURL`: cfg.CancelURL
     - `Metadata`: `map[string]string{"user_id": req.UserID, "plan_id": req.PlanID}` — critical for webhook to identify subscription
   - Call `session.New(params)`
   - Return session (URL, ID)

Create `src/server/internal/stripe/webhook.go`:

Per D-15: Webhook receives checkout.session.completed and updates subscription state.

1. Define `WebhookHandler`:
```go
type WebhookHandler struct {
    db      *sql.DB
    secret  string
}
func NewWebhookHandler(db *sql.DB, webhookSecret string) *WebhookHandler
```

2. Function `HandleWebhook(w http.ResponseWriter, r *http.Request)`:
   - Read body with `io.ReadAll(r.Body)` (limit to 64KB with `http.MaxBytesReader`)
   - Verify Stripe signature: `webhook.ConstructEvent(payload, r.Header.Get("Stripe-Signature"), h.secret)` — returns error with 400 if invalid
   - Switch on `event.Type`:
     - **`checkout.session.completed`**: Core handler for D-15.
       - Extract `user_id` and `plan_id` from `event.Data.Object.Metadata` (via `stripe.CheckoutSession` unmarshal)
       - Upsert subscription: INSERT INTO subscriptions (id, user_id, package_id, status, started_at, current_period_start, current_period_end, created_at)
         VALUES (uuid, $user_id, $plan_id, 'active', NOW(), NOW(), NOW() + INTERVAL '30 days', NOW())
         ON CONFLICT (user_id, package_id) DO UPDATE SET status='active', current_period_start=NOW(), current_period_end=NOW() + INTERVAL '30 days'
       - UPDATE users SET plan_id = $plan_id WHERE id = $user_id
       - INSERT audit_logs entry: action='plan.checkout_completed', resource_type='subscription', resource_id=$plan_id, actor_id=$user_id
       - Return 200 with `{"received": true}`
     - **`invoice.payment_succeeded`**: Log only (future use). Return 200.
     - **`customer.subscription.deleted`**: Handle cancellation. UPDATE subscriptions SET status='cancelled' WHERE user_id = (lookup via customer metadata). UPDATE users SET plan_id = NULL. Return 200.
     - Default: Return 200 (acknowledge unhandled events to prevent Stripe retries)

3. Use `encoding/json` for response, `io` for body reading, `net/http` for handler signature.

4. Stripe idempotency: Use `event.ID` as idempotency key. Before processing, SELECT FROM audit_logs WHERE action = 'stripe.webhook' AND resource_id = $eventID. If exists, return 200 (already processed). After processing, INSERT into audit_logs: action='stripe.webhook', resource_type='webhook', resource_id=$eventID, changes=(event type). This prevents duplicate processing per D-08 and Stripe best practices.

5. Error handling: If metadata missing (user_id or plan_id), still return 200 to Stripe (acknowledge receipt) but log the error — do NOT return 400 which would trigger Stripe retries on a permanently bad payload.

6. Add `github.com/stripe/stripe-go/v83` to go.mod if not already present. Run `cd src/server && go get github.com/stripe/stripe-go/v83` and `go mod tidy`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stripe webhook endpoint | Unauthenticated inbound HTTP from Stripe servers — signature verification is the sole trust mechanism |
| Checkout session metadata | user_id and plan_id pass through Stripe's redirect flow — must be validated on webhook receipt (plan exists, user exists) |
| Plan pricing data | Price amounts flow to Stripe as cents (int64) — no float rounding issues |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-09 | Spoofing | stripe/webhook.go | mitigate | Stripe signature verification via `webhook.ConstructEvent` using STRIPE_WEBHOOK_SECRET. Invalid signatures return 400 immediately. |
| T-03-10 | Repudiation | stripe/webhook.go | mitigate | All webhook events logged to audit_logs table with event ID as idempotency key. replay detection via audit_logs lookup before processing. |
| T-03-11 | Tampering | stripe/checkout.go | mitigate | Plan price fetched from DB at checkout creation time — user cannot modify price via client-side. Metadata (user_id, plan_id) set server-side in checkout session params. |
| T-03-12 | Information Disclosure | plan_service.go | mitigate | Public plan listing (IsPublic=true) exposes only plan metadata, no user subscription data. Admin plan listing requires RBAC (enforced at handler layer in Plan 06). |
| T-03-13 | Elevation of Privilege | plan_service SubscribeUser | mitigate | User can only subscribe to plans with is_public=true AND is_active=true. Deactivated or private plans are not subscribable. Actor identity from session middleware (Plan 06). |
| T-03-14 | Denial of Service | stripe/webhook.go | mitigate | Request body limited to 64KB via http.MaxBytesReader. Webhook idempotency prevents duplicate subscription insertion. |
</threat_model>
