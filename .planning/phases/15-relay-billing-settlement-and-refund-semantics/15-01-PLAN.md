<threat_model>
## Threat Model

| Threat | Severity | Mitigation in this plan |
|--------|----------|-------------------------|
| Provider returns HTTP 4xx/5xx without Go error and preauthorized quota remains stranded. | High | Router tests require refund on provider error responses and implementation treats status >= 400 as billing failure. |
| Provider returns a 2xx response without required usage and the call is neither settled nor refunded. | High | Router tests require refund and error for missing required usage on usage-settled endpoints. |
| Settlement or refund errors are swallowed, causing operators to believe quota state is correct. | High | Router tests require settlement/refund errors to propagate as `RouterError`. |
| Duplicate idempotency calls suppress quota calls but lose `QuotaSessionID`, causing later settlement/refund to hit no session. | High | BillingHook tests require fresh duplicate sessions to copy prior preauthorization and quota context. |
| Selected channel and request identity are missing from billing session evidence. | Medium | Router tests require selected channel ID and trusted request ID in quota preconsume/session context. |
| Streaming, realtime, file, batch, or async routes accidentally become commercial without settlement semantics. | High | Route policy/docs tests require explicit billing policy; unsupported flows remain production-disabled with reasons. |
</threat_model>
