# Phase 17 Plan: Stripe Payment Authority and Webhook Ledger

## Goal

Mount Stripe payment routes and create an auditable, tenant-aware, idempotent webhook ledger so v06 can safely build subscription, top-up, refund, and Marketplace settlement state machines on verified provider events.

## Requirements

- PAY-01
- PAY-02

## Implementation Plan

### 1. Add Payment Authority Schema

- Create `src/server/migrations/0028_payment_authority.sql`.
- Add `payment_intents` for checkout intent metadata:
  - `id`, `provider`, `provider_checkout_session_id`, `organization_id`, `user_id`, `package_id`, `kind`, `amount`, `currency`, `status`, `metadata`, timestamps.
- Add `stripe_webhook_events` for provider event idempotency:
  - `id`, `provider`, `event_id`, `event_type`, `status`, `organization_id`, `user_id`, `payment_intent_id`, `payload`, `error`, timestamps.
- Add unique indexes on provider checkout session ID and provider event ID.

### 2. Write RED Tests

- Add `src/server/internal/stripe/webhook_test.go` proving:
  - missing or invalid signature returns `400`;
  - a signed `checkout.session.completed` fixture records one `stripe_webhook_events` row;
  - replaying the same signed event returns `200` and does not insert a duplicate row.
- Add `src/server/internal/http/stripe_handler_test.go` proving:
  - `/api/v1/billing/stripe/webhook` is mounted and signature-protected without a session cookie;
  - `/api/v1/billing/checkout` requires a session and CSRF token;
  - an authenticated checkout request persists organization/user/package metadata and uses a fake checkout client.

### 3. Implement Store and Handler Boundaries

- Refactor `src/server/internal/stripe/webhook.go` to use a dedicated ledger store instead of `audit_logs`.
- Add checkout intent creation and a checkout client interface in `src/server/internal/stripe`.
- Add HTTP billing handler glue in `src/server/internal/http` so route tests can inject a fake checkout creator.
- Preserve raw-body webhook verification before JSON parsing.

### 4. Mount Routes

- Add Stripe configuration fields to `src/server/internal/config/config.go`.
- Mount:
  - `POST /api/v1/billing/checkout` behind `requireSession`.
  - `POST /api/v1/billing/stripe/webhook` without session, guarded only by Stripe signature verification.
- Keep `securityGuard` behavior compatible with webhook calls that do not carry a session cookie.

### 5. Verify and Record

- Run focused RED/GREEN commands from `17-CONTEXT.md`.
- Run docs checks and `git diff --check`.
- Update `.planning/STATE.md`, `.planning/REQUIREMENTS.md`, `.planning/ROADMAP.md`, and write `17-01-SUMMARY.md` only after verification passes.

## Completion Criteria

Phase 17 is complete only when PAY-01 and PAY-02 have current DB-backed route/store evidence and the docs clearly state that full subscription lifecycle, top-up fulfillment, refunds, invoices, Marketplace settlement, and admin billing UI remain required v06 work.
