## Threat Model

| Threat | Severity | Mitigation in this plan |
|--------|----------|-------------------------|
| Register/login/me expose different user shapes | High | Extend the response payload and tests to require `id`, `email`, `name`, and `role` in all three flows. |
| Blank names or roles break client assumptions | Medium | Populate deterministic defaults in the store path: `name=email` fallback and `role=user` fallback. |
| Admin checks weaken while role fields are normalized | High | Keep authority based on persisted role and existing `requireAdmin`; do not infer admin from response shape. |
| Preference defaults drift while auth response tests are updated | Medium | Add userprefs service tests for default mode/model/sidebar/notification settings. |
</threat_model>
