<threat_model>
## Threat Model

| Threat | Severity | Mitigation in this plan |
|--------|----------|-------------------------|
| A logged-in user can mark or delete another user's notification | High | Load the notification before mutation and require `notif.UserID == session.User.ID`. |
| Notification ownership checks regress when future route changes happen | High | Add handler-level and service-level tests for owner and non-owner outcomes. |
| Notification list/create remain session-gated but mutations become inconsistent | Medium | Keep list/create behavior unchanged and test only the mutation paths. |
</threat_model>
