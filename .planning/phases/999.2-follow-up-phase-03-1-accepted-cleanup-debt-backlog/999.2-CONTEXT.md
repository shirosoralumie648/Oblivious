## Implementation Decisions

### Legacy workspace MarketplacePage
- **D-01:** Treat `src/web/src/routes/workspace/MarketplacePage.tsx` as obsolete duplicate code, not as the active `/marketplace` implementation.
- **D-02:** The preferred execution plan should delete `src/web/src/routes/workspace/MarketplacePage.tsx` if planning verifies that no imports, routes, tests, or docs still depend on it.
- **D-03:** If deletion is risky because the file is untracked or user-owned in the current dirty worktree, the fallback is to archive or rename it with an explicit top-of-file pointer to the active `src/web/src/routes/marketplace/*` route tree.
- **D-04:** Do not wire the old workspace page back into the router. The active marketplace experience is already served from `src/web/src/routes/marketplace/*`.
- **D-05:** Do not migrate the static MCP server catalog from the legacy page into the Agent Marketplace in this cleanup phase. That would be new product scope and needs a separate feature phase.

### Requirements close policy
- **D-06:** Keep `.planning/REQUIREMENTS.md` as a living cross-phase context file for this repository.
- **D-07:** Future milestone completion should archive snapshots under `.planning/milestones/`, but should not reset or delete the living `.planning/REQUIREMENTS.md` unless a dedicated GSD policy migration is planned.
- **D-08:** If traceability needs cleanup, prefer small additive rows or notes for completed historical requirements over broad rewrites of `.planning/REQUIREMENTS.md`.

### Worktree boundaries
- **D-09:** Keep unrelated dirty worktree files out of Phase 999.2 unless the later plan explicitly claims them. In particular, do not touch `src/web/src/theme/tokens.css`, `src/web/tailwind.config.ts`, root historical docs, or reference reports.
- **D-10:** Phase 999.2 should remain cleanup-policy work. Do not expand it into root documentation consolidation, MCP marketplace redesign, or broad GSD workflow reform.

### Agent's Discretion
- The planner may choose the exact verification command set, but it must include a reference search for `MarketplacePage` and active route evidence before any deletion/archive step.
- The planner may decide whether the implementation step also updates nearby planning notes, as long as the edits stay narrowly scoped to the two backlog items.
- Exact wording of any archive comment or traceability note is flexible if the source-of-truth hierarchy remains clear.
