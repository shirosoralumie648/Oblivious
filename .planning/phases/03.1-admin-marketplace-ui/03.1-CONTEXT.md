<decisions>
## Implementation Decisions

### MVP 范围
- **D-01:** 全部 12 页面一次性实现：Admin 7 页（仪表板/渠道管理/路由管理/套餐管理/用户管理/审计日志/审核队列）+ Marketplace 5 页（首页/Agent详情/搜索浏览/发布流程/我的Agent）

### 开发优先级
- **D-02:** Admin 优先 — 先完成 Admin 7 页，后完成 Marketplace 5 页。Admin 是基础设施（渠道/用户/套餐管理先就绪），Marketplace 依赖管理端审核功能。

### 组件拆分与复用
- **D-03:** 提取通用组件库到 `src/web/src/features/shared/` 或 `src/web/src/components/`：
  - `DataTable` — 可排序/可分页/支持行内操作的数据表格（用于渠道列表、用户列表、路由列表、审核队列、Agent 列表）
  - `SearchBar` — 带防抖的搜索输入（用于用户搜索、Marketplace 搜索）
  - `FilterPanel` — 多维度筛选面板（标签/分类/评分/价格）
  - `MetricCard` — 指标卡片（仪表板用，大数字+标签+趋势箭头）
  - `StatChart` — 简单图表组件（仪表板用，复用现有指标数据）
  - `StatusBadge` — 状态徽章（渠道在线/离线、审核中/已批准/已拒绝）
  - `ConfirmDialog` — 确认弹窗（删除/禁用等危险操作）
  - `DrawerForm` — 抽屉式表单（渠道创建/编辑、套餐创建/编辑、路由配置）
  - `EmptyState` — 空状态占位（各页面无数据时）
  - `RatingStars` — 星级评分展示/交互组件

### API 集成与状态管理
- **D-04:** 使用现有 factory 模式 — 创建 `createAdminApi()` 和 `createMarketplaceApi()` 两个 API client
- **D-05:** 每个页面使用 `useReducer` + `useEffect` 管理请求状态（loading/error/data），遵循现有项目模式
- **D-06:** 复用现有 `createHttpClient()` — 继承 auth token 和错误处理

### Claude's Discretion
- DataTable 的具体列配置和排序逻辑
- MetricCard 的具体数值格式化
- 页面内 loading/error/empty 状态的具体 UI 实现（UI-SPEC 已定义文案）
- 组件文件的精确目录位置
</decisions>

<specifics>
## Specific Ideas

- DataTable 应支持客户端排序和分页，与后端 API 的分页参数对应
- 渠道状态指示器使用绿色/黄色/红色圆点（UI-SPEC 已定义 8px 状态点）
- 仪表板指标卡片应参考 Vercel/Linear 风格 — 简洁、大数字、微趋势指示
- 所有表单使用 DrawerForm（抽屉式），减少页面跳转
</specifics>
