# Plan 03.1-04 Summary: Admin Channels and Routes Pages

## Status

Completed.

## What Changed

- Replaced the Admin Channels placeholder with a full channel management page:
  - DataTable columns for name, provider, status, models, latency, and actions.
  - Search, provider filtering, sorting, row selection, and batch enable/disable.
  - Add/edit drawer form wired to the typed admin API client.
  - Delete confirmation flow.
  - Per-channel test connection action with loading state and tooltip feedback.
  - 30-second health polling with cleanup on unmount.
- Replaced the Admin Routes placeholder with a full model-route CRUD page:
  - DataTable columns for model pattern, target channel, priority, enabled state, and actions.
  - Add/edit drawer form backed by current route/channel API contracts.
  - Delete confirmation flow.
- Added focused tests for both pages.
- Fixed shared Radix composition issues needed by these pages:
  - `Button` now forwards refs for `asChild` consumers such as `TooltipTrigger`.
  - `DialogOverlay` and `SheetOverlay` now forward refs.
  - `DrawerForm` always renders a sheet description for accessibility.

## Deviations

- Used the live backend/frontend API contracts instead of stale plan field names:
  - Channels use `baseURL`, `rpmLimit`, and `tpmLimit`.
  - Channel batch updates call `batchUpdateChannels(ids, 'enable' | 'disable')`.
  - Routes use `{ model, strategy, channels: [{ channelID, weight, priority, enabled }] }`.
- The models field is implemented as a comma-separated input for this pass rather than a tag editor. It still serializes to the required `models: string[]` payload.
- Channel enable/disable is provided through row selection and batch actions; a per-row enable toggle can be added in a later polish pass if desired.
