<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| host Git -> Docker build args | Trusted clean-source identity crosses into a `.git`-free build context. |
| build args -> binary/OCI metadata | Caller-visible transport could be fabricated without post-build comparison. |
| binary inspection flag -> startup | Read-only identity inspection shares executable entrypoints with effectful runtime startup. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-31-05-01 | Spoofing | Docker build identity | high | mitigate | Derive outside Docker from clean Git, expose no identity overrides, and compare every post-build component. |
| T-31-05-02 | Tampering | binary/OCI/package tuple | high | mitigate | Same linker tuple, exact OCI labels, packaged digest recomputation, and fail on one-component mismatch. |
| T-31-05-03 | Elevation of Privilege | inspection startup path | high | mitigate | Shared handler executes before all config/DB/network work and returns handled status; zero-side-effect tests cover failures. |
| T-31-05-04 | Information Disclosure | inspection output | medium | mitigate | Output only public repository-local identity fields; no environment, credentials, DSN, or target evidence. |
| T-31-05-05 | Denial of Service | Docker availability | low | accept | Stage A package tests remain fast; Stage B explicitly fails rather than skips when Docker is unavailable. |
</threat_model>
