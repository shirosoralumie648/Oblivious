<threat_model>
## Threat Model

| Threat | Severity | Mitigation in this plan |
|--------|----------|-------------------------|
| Migration runner records a migration as applied when SQL failed. | High | Execute each migration and ledger insert in a transaction; commit only after SQL succeeds. |
| Existing migrations cannot be backfilled into `schema_migrations` because one migration has non-idempotent seed inserts. | High | Make `0024_categories_tags.sql` use `ON CONFLICT` before enabling ledger backfill. |
| Organization tenants become cosmetic while routes still rely only on user/workspace identity. | High | Add a dedicated `tenant` package and expose organization identity as a real persisted model; defer domain scoping explicitly to Phase 11. |
| Admin organization routes bypass admin guard. | High | Mount all organization routes under `requireAdmin` and add route-surface tests. |
| Unit tests pass but PostgreSQL behavior is unproven. | Medium | Add `TEST_DATABASE_URL` DB-backed tests for ledger and organization store behavior before phase close. |
</threat_model>

  <action>
  Refactor `cmd/migrate` so migration application is testable:
  - Add `ensureMigrationLedger(ctx, db)` that creates `schema_migrations`.
  - Add `loadMigrationFiles(dir)` that returns sorted `.sql` files.
  - Add `applyMigrations(ctx, db, dir)` that checks each filename/checksum against `schema_migrations`.
  - Compute SHA-256 checksum over the exact SQL file content.
  - If filename exists with same checksum, skip it.
  - If filename exists with different checksum, return an error containing `checksum mismatch`.
  - Execute migration SQL and insert ledger row in the same transaction.
  - Print an applied/skipped summary from `main()`.

  Make `0024_categories_tags.sql` idempotent by adding conflict handling to its seed insert:

  ```sql
  INSERT INTO categories (id, name, slug, display_order) VALUES
      ('cat_productivity', 'Productivity', 'productivity', 1),
      ('cat_research', 'Research', 'research', 2),
      ('cat_development', 'Development', 'development', 3),
      ('cat_creative', 'Creative', 'creative', 4),
      ('cat_education', 'Education', 'education', 5)
  ON CONFLICT (id) DO UPDATE SET
      name = EXCLUDED.name,
      slug = EXCLUDED.slug,
      display_order = EXCLUDED.display_order;
  ```
  </action>

  </verify>
  <acceptance_criteria>

  - Changing a previously recorded migration checksum returns an error containing `checksum mismatch`.

  </acceptance_criteria>

  Create `src/server/migrations/0025_tenant_foundation.sql` with:

  ```sql
  CREATE TABLE IF NOT EXISTS schema_migrations (
      version TEXT PRIMARY KEY,
      checksum TEXT NOT NULL,
      applied_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
  );

  CREATE TABLE IF NOT EXISTS organizations (
      id TEXT PRIMARY KEY,
      slug TEXT NOT NULL,
      name TEXT NOT NULL,
      status TEXT NOT NULL DEFAULT 'active',
      metadata JSONB NOT NULL DEFAULT '{}',
      created_by_user_id TEXT REFERENCES users(id) ON DELETE SET NULL,
      created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
      updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
      archived_at TIMESTAMPTZ,
      CHECK (slug ~ '^[a-z0-9][a-z0-9-]{1,61}[a-z0-9]$'),
      CHECK (status IN ('active', 'disabled', 'archived'))
  );

  CREATE UNIQUE INDEX IF NOT EXISTS idx_organizations_slug ON organizations(slug);
  CREATE INDEX IF NOT EXISTS idx_organizations_status ON organizations(status);
  CREATE INDEX IF NOT EXISTS idx_organizations_created_by ON organizations(created_by_user_id);
  ```
  </action>
