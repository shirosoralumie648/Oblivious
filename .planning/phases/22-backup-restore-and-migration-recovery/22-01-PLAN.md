<threat_model>
<threat severity="high" mitigation="Do not commit backup dumps, database URLs, passwords, or secret-bearing manifests. Default generated artifacts to .tmp/backups and keep manifests free of credentials.">
Backup files may contain customer data and secrets if handled carelessly.
</threat>
<threat severity="high" mitigation="Restore script must require an explicit target URL and smoke must use disposable/fresh databases. Production overwrite remains a documented manual operation outside automated smoke.">
An operator may accidentally restore into the wrong production database.
</threat>
<threat severity="medium" mitigation="Restore verification compares schema_migrations rows against checked-in migration filenames and SHA-256 checksums before recording OPS-03 success.">
A stale or corrupted dump could restore data while masking migration-ledger drift.
</threat>
<threat severity="medium" mitigation="Runbook documents encryption/storage boundary and requires operator-controlled encrypted storage before off-host transfer.">
Local unencrypted dumps may be copied to insecure storage.
</threat>
</threat_model>

<task type="tdd">
  <name>Task 1: Add PostgreSQL backup script</name>
  <files>scripts/backup-postgres.sh</files>
  <action>
  Create an operator backup script that writes a custom-format PostgreSQL dump and a non-secret manifest.
  </action>
  <implementation_contract>
  - Start with `#!/usr/bin/env bash` and `set -euo pipefail`.
  - Read the source URL from `BACKUP_DATABASE_URL`, falling back to `DATABASE_URL`.
  - If no source URL is present, print `[backup-postgres] BACKUP_DATABASE_URL or DATABASE_URL is required` and exit `2`.
  - Use host `pg_dump` when available. If it is missing, require Docker and run `pg_dump` inside `${PG_CLIENT_IMAGE:-${OBLIVIOUS_POSTGRES_IMAGE:-postgres:16}}` with the backup directory mounted into the container.
  - If neither host `pg_dump` nor Docker is available, print `[backup-postgres] pg_dump or docker is required` and exit `127`.
  - Use `BACKUP_DIR="${BACKUP_DIR:-.tmp/backups}"` and create the directory with mode `700`.
  - Use `BACKUP_BASENAME` if provided; otherwise use `oblivious-YYYYmmdd-HHMMSS`.
  - Write `${BACKUP_DIR}/${BACKUP_BASENAME}.dump` with `pg_dump --format=custom --no-owner --no-privileges --file "$dump_path" "$database_url"`.
  - Write `${BACKUP_DIR}/${BACKUP_BASENAME}.manifest` containing the UTC timestamp, dump filename, dump byte size, SHA-256 checksum, and a sanitized database URL class that does not include password material.
  - Print `[backup-postgres] backup written: <path>` and `[backup-postgres] manifest written: <path>`.
  </implementation_contract>
  <verify_red>
  <automated>env -u BACKUP_DATABASE_URL -u DATABASE_URL bash scripts/backup-postgres.sh</automated>
  <expected>FAIL with `BACKUP_DATABASE_URL or DATABASE_URL is required`.</expected>
  </verify_red>
</task>

<task type="tdd">
  <name>Task 2: Add restore script with migration ledger verification</name>
  <files>scripts/restore-postgres.sh</files>
  <action>
  Create an operator restore script that loads a dump into the target database and verifies `schema_migrations`.
  </action>
  <implementation_contract>
  - Start with `#!/usr/bin/env bash` and `set -euo pipefail`.
  - Read the target URL from `RESTORE_DATABASE_URL`, falling back to `DATABASE_URL`.
  - Require `BACKUP_FILE` and ensure it points at an existing file.
  - If no target URL is present, print `[restore-postgres] RESTORE_DATABASE_URL or DATABASE_URL is required` and exit `2`.
  - If `BACKUP_FILE` is missing, print `[restore-postgres] BACKUP_FILE is required` and exit `2`.
  - Use host `pg_restore` and `psql` when available. If either is missing, require Docker and run the PostgreSQL client command inside `${PG_CLIENT_IMAGE:-${OBLIVIOUS_POSTGRES_IMAGE:-postgres:16}}` with the repository and backup path mounted read-only/read-write as needed.
  - Require `sha256sum` on the host. Missing `sha256sum` exits `127`.
  - Run `pg_restore --clean --if-exists --no-owner --no-privileges --dbname "$database_url" "$BACKUP_FILE"`.
  - Verify every `src/server/migrations/*.sql` filename exists in `schema_migrations` with the SHA-256 checksum from `sha256sum`.
  - Verify no extra `schema_migrations` rows exist beyond checked-in migration filenames.
  - Print `[restore-postgres] migration ledger verified: <count> migrations`.
  </implementation_contract>
  <verify_red>
  <automated>env -u BACKUP_FILE RESTORE_DATABASE_URL=postgres://example:example@127.0.0.1:1/example bash scripts/restore-postgres.sh</automated>
  <expected>FAIL with `BACKUP_FILE is required` before attempting a network connection.</expected>
  </verify_red>
</task>

<task type="tdd">
  <name>Task 3: Add automated backup/restore smoke</name>
  <files>scripts/backup-restore-smoke.sh</files>
  <action>
  Create a smoke script that applies migrations, inserts commercial tenant fixture data, backs up the source database, restores into a fresh database, and verifies restored data.
  </action>
  <implementation_contract>
  - Start with `#!/usr/bin/env bash` and `set -euo pipefail`.
  - Resolve PostgreSQL client commands the same way as the backup/restore scripts: prefer host tools, fall back to Docker client execution.
  - If `BACKUP_SMOKE_SOURCE_DATABASE_URL` and `BACKUP_SMOKE_RESTORE_DATABASE_URL` are provided, use those disposable databases.
  - If either URL is missing, require Docker and start two disposable pgvector-capable PostgreSQL containers with unique `oblivious-phase22-*` names, random host ports, database `oblivious`, user `oblivious`, and password `oblivious`.
  - Use `OBLIVIOUS_POSTGRES_IMAGE="${OBLIVIOUS_POSTGRES_IMAGE:-pgvector/pgvector:pg16}"`.
  - Wait for both databases with `pg_isready` or `psql 'SELECT 1'`.
  - Apply migrations to the source with `cd src/server && DATABASE_URL="$source_url" go run ./cmd/migrate`.
  - Insert deterministic `phase22_` fixture rows in dependency order for users, organizations, organization memberships, quotas, billing sessions, packages, subscriptions, top-ups, payment intents, Stripe webhook events, billing lifecycle events, invoices, refunds, published agents, versions, installs, Marketplace orders, payouts, settlements, governance events, abuse reports, and audit logs.
  - Call `scripts/backup-postgres.sh` with `BACKUP_DATABASE_URL="$source_url"` and an ignored `.tmp/backups/phase22-*` path.
  - Call `scripts/restore-postgres.sh` with `RESTORE_DATABASE_URL="$restore_url"` and `BACKUP_FILE` pointing at the generated dump.
  - Verify restored fixture rows with specific `SELECT COUNT(*)` assertions for each required category and fail on any mismatch.
  - Print `[backup-restore-smoke] backup/restore smoke ok` only after fixture and migration ledger checks pass.
  </implementation_contract>
  <verify_green>
  <automated>bash scripts/backup-restore-smoke.sh</automated>
  <expected>PASS when Go, Docker, and a pgvector-capable image are available; host PostgreSQL client tools are optional because the scripts can use Docker client execution.</expected>
  </verify_green>
</task>
