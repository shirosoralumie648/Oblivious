# Phase 31.1 - Validation Strategy

> Per-phase validation contract for dynamic runtime authorization and repository-local deployment proof.

The current plan set contains ten plans and 28 executable tasks across seven waves. The final dependency order first builds disjoint consumer packages, then the real live Agent ToolExecutor and exact model/tool response DTOs, then sole-owner server composition, remaining roots, exact coverage join/typed report CLI, and deployment proof. This covers 12 real standalone roots, direct-Tavily/configured-Chain/builtin web search, live custom HTTP/local Python/sandbox/MCP effects, and standalone/aggregate immutable-image harness modes while retaining the per-plan nine-file cap. The maps below bind every task and Wave 0 artifact to a concrete non-vacuous command. `nyquist_compliant: true` records continuous planned automated coverage derived from this plan map only; `wave_0_complete: false` remains authoritative until implementation creates and passes those suites/scripts, and no checker pass is claimed here.

The required helper contract is `bash scripts/run-go-tests-matched.sh <one package pattern> <anchored top-level suite regex> [go-test-args...]` from the repository root. It first lists matching tests and fails unless the required package contains the exact suite, then executes under `src/server`. A row covering multiple packages chains one invocation per package; broad OR-regex existence checks are not evidence. The suite owns table/subtests for every behavior named in its row. Phase 31 Plan 31-02 must deliver this exact CLI before Phase 31.1 implementation; direct targeted Go selectors and the obsolete separator form are forbidden.

## Sampling Rate

- **implementation/verification per behavior:** first run the named narrow test and observe the expected failure, implement the minimum behavior, rerun to passing.
- **After every task:** run its automated command plus the directly affected package tests and `git diff --check`.
- **After Wave 1:** run Plan 01 evaluator/manager/catalog/report suites, including the race selector.
- **After Wave 2:** rerun all Wave 1/2 focused suites; worker, Relay/Chat, workflow adapter injection, MCP/independent Registry/Chain and finance constructors must compile and pass without `server.go` or the not-yet-created expected manifest. `ModelOption{id,label,capabilityId}` compiles in Go/TypeScript and mutation rejects capabilityId. Each constructor registers owned descriptors once; same-instance double effects re-guard twice without changing registrar counts, while duplicate construction fails.
- **After Wave 3:** run direct Tavily/configured Chain/factory plus `TestLiveAgentToolExecutorReadinessContract` and `agentsApi.test.ts`; Tavily/WebSearch/ToolExecutor constructors register once, builtin/custom HTTP/local Python/sandbox/MCP calls re-guard on both attempts, live ToolDefinition capabilityId is response-only, second-call expiry keeps downstream zero, and Registry coverage is explicitly insufficient.
- **After Wave 4:** run group-one preflight, immutable input handoff, BuildRuntime lifecycle and startup-order suites; contract/profile/identity resolve once and all completed consumers receive one RuntimeAuthorities carrier.
- **After Wave 5:** run both standalone preflight suites and all prior focused suites; all 12 excluded roots must have zero dependency/effect registration and exact immutable callback inputs.
- **After Wave 6:** run every focused suite and `git diff --check`; Plan 03 creates/exact-joins the expected manifest and compiles both `report-readiness` and `report-deployment` commands here.
- **After Wave 7:** run the moved readiness fixtures, static deployment validation, standalone-build harness, aggregate-consume no-rebuild fixtures, and `bash scripts/verify-readiness-contract.sh stage-a --output-dir .tmp/phase-31.1-stage-a`.
- **Stage A during development:** run identity-independent behavior and identity substitution in temporary clean Git fixtures; the product worktree may be dirty and cannot produce a release pass.
- **Stage B after identity-bearing commit:** run binary/OCI/packaged-contract/runtime-audit identity checks against the exact clean `HEAD`; do not push that commit until Stage B passes, and invalidate the result after any new commit.
- **Before phase verification:** run the full phase command, focused race suite, existing quality gate and scope/claim scans from the exact clean committed checkout.
- **No skip conversion:** missing Docker/DB can shorten local feedback only; it cannot satisfy or skip the committed harness row.
