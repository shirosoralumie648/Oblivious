## Decisions Made

- Strict Router callers cannot supply an Admin service because a constructed service cannot prove it carries the current startup authority; compatibility tests continue through the non-strict entrypoint.
- Generic model mutation admission is distinct from model catalog authorization. The generic guard runs once at public entry, while every returned/persisted subject is still resolved from the current server catalog before a write.
- The Marketplace HTTP layer and SettlementService consume the same immutable startup carrier but guard their own effects independently; no readiness generation is pinned across local intent and Provider dispatch.
- Once local intent exists, a later readiness denial is a compensating state transition rather than a zero-mutation return; the original readiness response is preserved only after that transition succeeds.
- Compatibility runtime construction is reachable only from `NewServer`; production `BuildRuntime` and its private builder have exactly one strict Router entrypoint and no direct or wrapper-mediated legacy entrypoint.
