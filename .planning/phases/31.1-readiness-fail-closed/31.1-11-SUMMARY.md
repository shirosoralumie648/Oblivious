**Generation-one bootstrap is linearizable, every dependency has one capacity-bounded probe lane, and deadline cancellation always wins before a probe completion can authorize a candidate.**

## Accomplishments

- Added a dedicated bootstrap transition mutex covering the initial-state check through generation-one refresh and publication. The 64-caller race contract proves one success, 63 stable `readiness_unavailable` failures, generation 1, one complete applicable probe set, and one audit write.
- Compiled a capacity-one in-flight lane for every applicable dependency. Occupied lanes synthesize `dependency_unproven` without launching another goroutine, while other dependencies continue producing structurally complete candidates.
- Proved that releasing a stuck invocation does not mutate an older generation and makes the dependency lane reusable by a later refresh.
- Added explicit completion arbitration that checks cancellation before waiting and again after receiving a result, preventing an enabled result returned after expiry from authorizing the candidate.

## Decisions Made

- Bootstrap uses a dedicated transition mutex rather than overloading publication locking, so generation-one ownership is explicit while ordinary publication behavior remains unchanged.
- Each managed dependency owns one nonblocking capacity-one lane. An occupied lane produces the same typed blocked observation as a timeout and never permits a late result to cross candidate boundaries.
- Probe completion is accepted only after cancellation checks on both sides of the blocking receive; this gives observed deadline cancellation deterministic precedence when both cases are ready.
