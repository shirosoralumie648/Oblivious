## Decisions Made

- Keep legacy constructors available for isolated callers until Plan 31.1-02 switches production composition; all new readiness constructors fail closed on missing carrier/binding.
- Treat returned capability metadata as diagnostic/read-only data. Later execution resolves the model again from the current server catalog and never trusts a persisted or UI-selected capability ID.
- Validate raw channel probe/persisted model arrays before `normalizeProbeModels`; silent de-duplication must not turn ambiguous input into an authorized write.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Split combined Relay model/provider checks and make guarded route fallback fail closed**
- **Found during:** Task 1 (per-attempt Relay contract test)
- **Issue:** The interrupted partial helper combined both checks and the first test used only one channel, so a retry could exhaust routing without reaching a fresh readiness denial.
- **Fix:** Added explicit model/provider gates, derived a unique model from the current route channel, and expanded the test to two-channel billing and non-billing retries with downstream counters.
- **Files modified:** `src/server/internal/relay/router.go`, `src/server/internal/relay/router_test.go`
- **Verification:** Focused Relay suite and `go test ./internal/relay ./internal/releasecontract -count=1` pass.
- **Committed in:** `e50d0e0`

**2. [Rule 2 - Missing Critical] Prevent canceled Chat requests from authorizing a fallback attempt**
- **Found during:** Task 2 (fallback boundary tests)
- **Issue:** Existing CompositeGateway fallback classification included `context.Canceled` and `context.DeadlineExceeded`, which could start a second effect after the caller had canceled.
- **Fix:** Return cancellation/deadline errors before fallback classification and require current readiness before any non-canceled fallback.
- **Files modified:** `src/server/internal/chat/relay_gateway.go`, `src/server/internal/chat/relay_gateway_test.go`
- **Verification:** Chat readiness suite and full Go regression pass.
- **Committed in:** `bd5a772`

**3. [Rule 2 - Missing Critical] Reject ambiguous raw channel model lists before normalization**
- **Found during:** Task 3 (Admin catalog mutation contract)
- **Issue:** `normalizeProbeModels` de-duplicated repeated upstream/persisted values before authorization, allowing ambiguous subjects to reach persistence.
- **Fix:** Validate raw probe and persisted lists through the current catalog before normalization; retain atomic zero-write behavior on failure.
- **Files modified:** `src/server/internal/admin/channel_service.go`, `src/server/internal/admin/service_test.go`
- **Verification:** Admin model mutation suite and full Go regression pass.
- **Committed in:** `94d8968`

**4. [Rule 2 - Missing Critical] Add Service-owned readiness injection seam for Admin mutations**
- **Found during:** Task 3 (constructor integration)
- **Issue:** `Service` had no owner field or constructor path for the required startup `RuntimeAuthorities`, so channel mutation guards could not be composed without a parallel/global authority.
- **Fix:** Added `modelReadiness`, `ModelCatalogRuntimeOptions`, and `NewReadinessService` in the Service owner file.
- **Files modified:** `src/server/internal/admin/service.go`
- **Verification:** Admin focused suite, full Go regression, and constructor fail-closed test pass.
- **Committed in:** `94d8968`
