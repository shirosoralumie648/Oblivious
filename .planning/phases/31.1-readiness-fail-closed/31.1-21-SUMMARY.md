**Chat mutations now accept exactly one strict JSON object and reject every trailing value or malformed token before model, persistence, Relay, or usage work.**

## Accomplishments

- `decodeStrictChatMutation` retains `DisallowUnknownFields`, decodes the request DTO once, then performs a second standards-compliant decode and accepts only `io.EOF`.
- The decoder matrix accepts a single object with spaces, tabs, carriage returns, and newlines; it rejects a second object, scalar, array, `null`, malformed trailing token, scalar/array first document, unknown field, and malformed first object.
- Real `sendMessage` handler regressions prove every trailing-input class leaves model guard/config lookup, message store reads and writes, Relay reply generation, and usage recording at zero.
- The positive control reaches the expected guard, store, Relay, and usage counters, proving rejected-case zero counts do not come from disconnected spies.
- Rejections retain HTTP 400 and the exact `invalid_request` / `invalid json body` envelope, with a seeded secret-like trailing value absent from the response.
