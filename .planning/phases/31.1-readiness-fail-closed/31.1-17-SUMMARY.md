## Accomplishments

- `config.Load` retains `REDIS_URL` for readiness under memory/none rate limiting, preserves explicit Redis override precedence, and returns a fresh typed `KafkaBrokers` list after strict host/port parsing.
- Normal server startup passes loaded config plus the already-open PostgreSQL handle into a five-probe factory before `Bootstrap`; the former `OBLIVIOUS_READINESS_PROBE_BASE_URL` startup authority and placeholder probes are removed.
- PostgreSQL uses the existing `PingContext`; Redis uses attempt-scoped `PING`; Qdrant uses bounded `GET /healthz`; ClickHouse uses attempt-scoped `PingContext`; Kafka performs bounded dial plus metadata and closes the connection.
- Default Compose starts Kafka, waits on all five dependencies, and supplies `KAFKA_BROKERS`; Kubernetes ConfigMap supplies the existing in-cluster Kafka Service address without modifying the Plan 22 runner or Kafka manifest.
- The clean-commit Docker harness starts five real dependencies and proves healthy, selected-Qdrant blocked, restored, evaluator-stale, and final restored readiness while keeping audit evidence output-only.

## Decisions Made

- Treat missing endpoint configuration as a real typed blocked probe rather than removing the dependency or inventing local defaults; malformed endpoint syntax fails construction with stable text.
- Use a Qdrant-only forwarding proxy for deterministic E2 fault injection. Healthy requests still reach the real Qdrant `/healthz`; the proxy cannot authorize PostgreSQL, Redis, ClickHouse, or Kafka.
- Produce stale proof by suspending the shipped server beyond authored max age and queueing `/readyz` requests, then prove refresh recovery after resume; no audit timestamp or caller-controlled availability is used.
