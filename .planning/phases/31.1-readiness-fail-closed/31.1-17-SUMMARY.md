## Accomplishments

- `config.Load` retains `REDIS_URL` for readiness under memory/none rate limiting, preserves explicit Redis override precedence, and returns a fresh typed `KafkaBrokers` list after strict IP/DNS host and port validation.
- Normal server startup passes loaded config plus the already-open PostgreSQL handle into a five-probe factory before `Bootstrap`; the former `OBLIVIOUS_READINESS_PROBE_BASE_URL` startup authority and placeholder probes are removed.
- PostgreSQL uses the existing `PingContext`; Redis uses attempt-scoped `PING`; Qdrant uses bounded `GET /healthz`; ClickHouse uses attempt-scoped `PingContext`; Kafka performs bounded dial plus metadata and closes the connection.
- Post-plan transport hardening preserves `rediss://` as verified TLS 1.2+, rejects all Qdrant redirects before custom credential forwarding, and probes Kafka brokers concurrently so an earlier blackhole cannot consume the shared deadline before a healthy later broker is tried.
- Redis transport parity now extends beyond readiness: monolith and standalone Relay rate limiters use the same strict internal Config helper, prove plaintext/TLS wire behavior with real listeners, and return redacted constructor errors instead of silently creating plaintext clients.
- Default Compose starts Kafka, waits on all five dependencies, and supplies `KAFKA_BROKERS`; Kubernetes ConfigMap supplies the existing in-cluster Kafka Service address without modifying the Plan 22 runner or Kafka manifest.
- The clean-commit Docker harness starts five real dependencies and proves healthy, selected-Qdrant blocked, restored, evaluator-stale, and final restored readiness while keeping audit evidence output-only.

## Decisions Made

- Treat missing endpoint configuration as a real typed blocked probe rather than removing the dependency or inventing local defaults; malformed endpoint syntax fails construction with stable text.
- Keep duplicate brokers valid and ordered, but reject every non-IP host that is not a strict ASCII DNS name; the internal config package owns the narrow shared validator used by both environment loading and server construction.
- Use a Qdrant-only forwarding proxy for deterministic E2 fault injection. Healthy requests still reach the real Qdrant `/healthz`; the proxy cannot authorize PostgreSQL, Redis, ClickHouse, or Kafka.
- Produce stale proof by suspending the shipped server beyond authored max age and queueing `/readyz` requests, then prove refresh recovery after resume; no audit timestamp or caller-controlled availability is used.

**4. [Rule 1 - Security] Rejected malformed Kafka host text beyond SplitHostPort syntax**
- **Found during:** post-plan code review.
- **Issue:** `net.SplitHostPort` validates delimiter shape, not DNS/IP semantics, so whitespace/control/path/query/userinfo and malformed DNS names could become deployment dial targets.
- **Fix:** Added one strict internal config validator and reused it for env-loaded and programmatic broker lists with stable redacted caller-specific errors.
- **Verification:** expanded anchored selectors, full package regression, focused race, vet, fixtures, Compose parsing, and diff hygiene passed.
- **Committed in:** `37e5d94`.

**5. [Rule 1 - Security] Rejected credential-bearing Qdrant redirects**
- **Found during:** post-plan transport review.
- **Issue:** Go's default HTTP client followed same-origin and cross-origin redirects while retaining the custom `api-key` header, allowing deployment-controlled redirect responses to exfiltrate the credential.
- **Fix:** Set a fail-closed redirect policy that returns the 3xx response to the probe; the existing non-2xx health rule blocks it without reading or exposing a response body.
- **Verification:** Real `httptest` source/target servers prove both redirect classes are rejected and the target receives zero calls.
- **Committed in:** `373340f`.

**6. [Rule 1 - Security] Preserved rediss transport semantics through typed config**
- **Found during:** post-plan transport review.
- **Issue:** `parseRedisURL` accepted `rediss://` but discarded the scheme, so the readiness client downgraded it to plaintext Redis.
- **Fix:** Carry `Config.RedisTLS` from the URL scheme through explicit endpoint/password/DB overrides and construct TLS 1.2+ options with host-derived ServerName and certificate verification enabled; malformed TLS addresses fail with stable redacted text.
- **Verification:** Config precedence rows, option-policy assertions, and a real listener prove `redis://` begins RESP while `rediss://` begins a TLS ClientHello.
- **Committed in:** `373340f`.

**7. [Rule 1 - Bug] Prevented first-broker starvation in Kafka readiness**
- **Found during:** post-plan transport review.
- **Issue:** serial metadata attempts shared one outer deadline, so an accepted blackhole broker could exhaust the budget before a healthy later broker was dialed.
- **Fix:** Run all validated brokers concurrently under one child context, accept the first successful metadata result, cancel peers, buffer result delivery, and close connected attempts on cancellation.
- **Verification:** deterministic attempt injection proves first-success peer cancellation and redacted all-fail handling; real listeners prove concurrent dialing and connection cleanup; focused race passes ten repetitions.
- **Committed in:** `373340f`.

**8. [Rule 1 - Security] Preserved Redis TLS across Relay rate limiter runtimes**
- **Found during:** independent post-fix quality review.
- **Issue:** readiness honored `Config.RedisTLS`, but monolith HTTP and standalone Relay each rebuilt plaintext `redis.Options`, silently downgrading the same `rediss://` configuration for rate limiting.
- **Fix:** Moved strict options construction into `internal/config.RedisClientOptions`, reused it in all three internal Config consumers, changed both limiter constructors to return errors, and propagated failures through monolith runtime construction and standalone entrypoint startup.
- **Verification:** Shared option-policy rows plus real-listener monolith/standalone limiter tests prove plaintext RESP, TLS ClientHello, TLS 1.2 minimum, SNI/certificate verification, and stable redacted invalid-address failure; full affected packages and focused race pass.
- **Scope decision:** `internal/gateway` consumes independent `pkg/config.GatewayConfig/CommonConfig`, not `internal/config.Config`; its separate scheme contract was inspected and deliberately not folded into this Plan 17 parity change.
- **Committed in:** `2c06955`.

**9. [Rule 1 - Security] Rejected malformed plaintext and TLS Redis endpoints before client construction**
- **Found during:** Revision 1 independent spec review.
- **Issue:** `RedisClientOptions` returned plaintext options before validating any address, while its TLS branch used only `net.SplitHostPort`; programmatic Config therefore accepted whitespace/control/path/query/userinfo and malformed DNS values, contradicting the fail-closed constructor claim.
- **Fix:** Extracted the existing strict Kafka endpoint semantics into a generic private `validateHostPortEndpoint`, retained Kafka's public stable wrapper, and required both Redis modes to pass the generic validator before allocating options. Plaintext and TLS retain distinct stable redacted error strings.
- **Verification:** Table-driven helper tests cover 22 malformed mode/address rows; monolith and standalone Relay each prove all 22 rows return nil limiter/closer with no raw value; existing valid DNS/IP Redis behavior, Kafka config matrix, full packages, race, vet, fixtures, and Compose parsing pass.
- **Committed in:** `1187891`.
