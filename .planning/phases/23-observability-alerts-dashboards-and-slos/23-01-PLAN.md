<threat severity="high" mitigation="Structured logs and error reports must never include prompt text, response text, API keys, Stripe raw payloads, cookie values, authorization headers, database URLs, or webhook secrets. Tests must assert representative sensitive strings are absent.">
Observability can leak customer data or secrets.
</threat>
<threat severity="high" mitigation="Metrics labels must use normalized route names, classes, event names, and status values. Do not use raw URL paths, emails, provider error messages, request bodies, or tenant names as labels.">
High-cardinality metrics can make Prometheus unusable during incidents.
</threat>
<threat severity="medium" mitigation="OpenTelemetry and error-reporting exporters must be optional no-op defaults; startup must not fail because external observability vendors are unavailable.">
External observability dependencies could become production availability dependencies.
</threat>
<threat severity="medium" mitigation="Alert rules must use metrics produced in this repository and must include owner/severity/runbook labels so Phase 24 can verify incident flow.">
Alerts may be decorative if they reference nonexistent metrics or lack ownership.
</threat>
</threat_model>
