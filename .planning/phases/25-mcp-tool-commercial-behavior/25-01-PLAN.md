<threat_model>
<threat severity="high" mitigation="Disable provider-backed or egress-capable built-ins by default unless this phase implements real provider configuration and tenant-safe policy with tests.">
Placeholder or raw outbound built-ins can become customer-facing commercial behavior through Agent tool execution.
</threat>
<threat severity="high" mitigation="Agent executor must block disabled built-ins at both tool-definition generation and execution time so stale Agent JSON cannot bypass policy.">
Filtering only UI or docs would still allow existing Agent configs to execute disabled tools.
</threat>
<threat severity="high" mitigation="`http_request` must not perform any network I/O in its disabled default path.">
Default outbound HTTP can create SSRF, data exfiltration, and tenant policy bypass risk.
</threat>
<threat severity="medium" mitigation="Calculator parser should implement a small grammar instead of delegating to shell, JavaScript, SQL, or unchecked reflection.">
A permissive evaluator could introduce injection or nondeterministic behavior.
</threat>
</threat_model>

<task type="code">
  <name>Task 2: Implement builtin availability metadata and calculator parser</name>
  <files>src/server/internal/mcp/builtin.go</files>
  <action>
  Make builtin behavior match the Phase 25 policy.
  </action>
  <implementation_contract>
  - Add metadata or methods that distinguish default commercial enabled tools from disabled/provider-dependent tools.
  - Keep `BuiltinTools` compatible for existing callers, but add a policy-aware listing function such as `ListDefaultCommercialBuiltinTools`.
  - Implement `calculator` with a small parser for numeric arithmetic, parentheses, unary signs, `+`, `-`, `*`, and `/`.
  - Return deterministic content such as `Result: 7` or `Result: 2`; normalize integer-looking floats without excessive trailing zeros.
  - Reject malformed expressions, unsupported characters, trailing tokens, empty expressions, and division by zero with explicit errors.
  - Make `web_search` disabled by default with a message that says a search provider is not configured.
  - Make `http_request` disabled by default unless an explicit policy is introduced in this phase; the default execution path must return before creating or sending an HTTP request.
  - Ensure default-enabled built-ins never include the word `placeholder` in returned customer-facing content.
  </implementation_contract>
  <verify_green>
  <automated>cd src/server && go test ./internal/mcp -run 'Builtin|Calculator|Disabled' -count=1</automated>
  <expected>PASS after implementation.</expected>
  </verify_green>
</task>
