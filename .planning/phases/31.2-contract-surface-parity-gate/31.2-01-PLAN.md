<interfaces>
Phase 31 and 31.1 are unexecuted hard dependencies at planning time. Before implementation, require the implemented `config/release/contract.v1.json` capability/surface IDs and correct those upstream owners if their declared contracts differ; do not author a second capability registry here.

The projector owns one closed scope and this exact metadata contract:

`PublicOperationScopeV1{mandatoryPrefixes:["/api/","/v1/"],dispositions:[{method,normalizedPath,disposition,reason}]}`

`SchemaIdentityV1 = {kind:"ref",value:canonicalRef} | {kind:"inline",value:"sha256:<64hex>"} | {kind:"none",value:null}`

`OperationContractMetadataV1{method,normalizedPath,operationId,security,csrf,capabilityId,request:{mediaType,schemaIdentity},successResponses:[{status,mediaType,schemaIdentity}]}`

Every `/api/*` and `/v1/*` operation is included and cannot be dispositioned away. Every other OpenAPI public operation must carry one explicit included/excluded disposition; included rows receive the full metadata, while excluded rows retain method/path/reason only and cannot silently disappear. Inline schemas use a canonical SHA-256 identity; `$ref` values remain canonical references. Arrays and JSON keys are deterministically sorted. Browser encoder, decoder, and event identity are absent from this tuple.

`verify_frontend_operation_contract_usage.mjs` is a narrow prerequisite checker, not the Phase 03 production inventory authority. It builds a TypeScript Program for explicit `--expect-owner` files, resolves imports from `@/generated/operation-contracts.generated`, and proves each caller passes an exact generated `OperationContractMetadataV1` symbol into the shared HttpClient/stream/upload/SWR transport. It emits nonzero owner/import/use/disposition counts and rejects path/core lookup, locally reconstructed metadata, and generic-only identity. Phase 03 later performs complete discovery and unknown-caller closure.
</interfaces>
