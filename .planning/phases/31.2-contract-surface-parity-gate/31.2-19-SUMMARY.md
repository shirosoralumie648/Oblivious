## Decisions Made

- Route-attempt identity is server-generated (crypto/rand 16 bytes → hex) before either preauthorization; failure returns a sanitized `route_attempt_identity_generation_failed` error before any reservation side effect. Caller idempotency key may remain a correlation input but is never the uniqueness root.
- `directFallback` calls `QuotaManager.Refund` when `billingSessionID != ""` (not gated on `organizationID != ""`), preserving original router behavior where tests without an org context still get refunds from stubs.
- `QuotaCompensationWorker` is always active when SQL-backed Relay billing is wired — there is no per-config toggle to silently strand jobs.
- The worker uses `RefundRelayAPITokenQuotaOnce` (durable receipt) while the direct-fallback path uses `RefundRelayAPITokenQuota` (simple decrement); the crash-window is closed because the receipt acts as the idempotency key.

- **Found during:** Task 1 verification (TestQuotaCompensationStoreClaimsLeasedJobs)
