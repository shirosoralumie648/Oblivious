# Phase 31.2: Plan 18 Summary

**External migration replay now enforces whole-database freshness preflight and migrates only a session-owned disposable database with verified teardown**

## Performance

- **Duration:** ~35 min
- **Completed:** 2026-07-26
- **Tasks:** 2
- **Files modified:** 2

## Accomplishments

- `prepare_external_database()` refactored: caller URL is a maintenance-only connection; queries `pg_catalog.pg_namespace` and `pg_catalog.pg_class` to reject any non-system schema or user relation before creating effects; contaminated candidates set `resource_ownership=caller-owned` and fail session without invoking migrate
- Owned disposable database created with collision-resistant name (PID+RANDOM) via maintenance connection; `database_url` is set to the owned DB exclusively
- `cleanup_resources()` drops the owned DB and verifies absence via `pg_catalog.pg_database COUNT(1)` before setting `cleanup_result=succeeded`
- `write_failure_observation` and `write_pass_observation` both emit `resourceOwnership` field
- `verify_success_reports` asserts `resourceOwnership=owned-disposable` as a required condition for pass
- RED fixture cases: 4 contaminated scenarios (table+row, sequence, empty relation, extra schema) prove false-green behavior before implementation; 1 clean-candidate PASS case proves owned lifecycle
- psql/createdb/dropdb shims extended to delegate catalog queries and owned-DB lifecycle to real PostgreSQL via docker exec
