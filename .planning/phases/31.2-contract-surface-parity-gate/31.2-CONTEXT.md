<domain>
## Phase Boundary

本阶段只关闭 `RELS-02`：让 OpenAPI、Go runtime routes、frontend transports 与产品呈现、protobuf source/generated outputs、monolith migration inventory/ledger/replay 对同一个 trusted release identity 双向一致，并由唯一 aggregate owner 在 drift、identity splice、重复 surface 或 committed skip 时阻断发布。

本阶段消费 Phase 31 交付的 authored contract、`BuildIdentityV1`、嵌套 `SurfaceReportV1`、typed details-registry API、trusted identity resolver、atomic report writer 和 foundation build report，也消费 Phase 31.1 交付的 `ReadinessManager` inspector、独立 readiness/deployment reports 及 server-derived catalog `capabilityId`。本阶段不得复制这些权威类型、重新计算 freshness，或在 frontend 再维护 model/tool 到 capability 的映射。

本阶段只形成 E1 static/fixture 与 E2 repository-local runtime/replay 证据。E3 target evidence、E4 same-commit commercial proof、非 monolith profile parity、SBOM/provenance/signature、真实 Provider/支付/观测/恢复证据仍由 Phase 32-39 负责。

</domain>

<decisions>
## Trackable Decisions

### HTTP/OpenAPI/runtime 双向一致性

- **D-SUR-01:** `docs/api/openapi.yaml` 继续是 HTTP public contract 的 canonical source；`docs/api/route-surface-manifest.json` 只能是确定性派生产物。每个 operation 必须携带稳定 capability ID，release contract 只引用 capability/surface，不复制 request 或 response schema。
- **D-SUR-02:** OpenAPI operation、derived route manifest 和 runtime registry 使用同一个 server-core fingerprint：normalized method/path、operation ID、security/CSRF、capability ID、request media/schema ref，以及每个声明 success response 的 status/media/schema ref。frontend sidecar 在该 core 上增加 transport kind、request encoder、response decoder 和 SSE/WebSocket event identity，并按 media/schema compatibility rules join；Go runtime descriptor 不拥有 browser encoder/decoder。任一方向的 missing、extra 或 incompatible 都失败；只比较 route existence 不足以通过。
- **D-SUR-03:** runtime registry 必须暴露可验证的 route descriptor，而不是由测试猜测 handler 行为。descriptor 可以引用 OpenAPI-owned schema ref/digest，但不得复制 schema body。excluded operation 不得注册；Phase 31.1 的 disabled/blocked guard 结果仍由 runtime policy 负责，本阶段只验证 descriptor、注册结果和 capability identity 一致。
- **D-SUR-04:** `/api/v1/app/conversations/{conversationId}/export.md` 保持 `text/markdown`，runtime 的 `text/markdown; charset=utf-8` 与 OpenAPI base media type视为兼容；frontend 必须通过 shared typed text decoder 发送 `Accept: text/markdown`、接受 charset parameter、调用 `response.text()`，且不进入 JSON envelope decoder。

### Production-only TypeScript AST sidecar

- **D-SUR-05:** 使用仓库已安装的 TypeScript compiler API 生成唯一 `frontend-surface-sidecar/v1`。扫描 root 固定为 `src/web/src/**/*.{ts,tsx}`；production caller 排除 `*.test.*`、`*.spec.*`、`__tests__`、`test` support、fixtures、mocks 和 snapshots。generated modules 作为 stale consumer 单独检查，但不得被计作 transport call source。
- **D-SUR-06:** sidecar 必须分类所有 production `HttpClient`、direct `fetch`/`fetchFn`、SWR fetcher、multipart upload、`streamText`/SSE、`EventSource` 和 `WebSocket` call。动态 path/method/media/decoder 无法静态解析、未分类 transport、未知 wrapper 或扫描结果为空均失败。负向样例位于独立 fixture source root，不能混入 production scan。
- **D-SUR-07:** transport parity verifier 与 product exposure verifier 必须消费同一份 sidecar，不能分别解析 TypeScript。sidecar 同时记录 operation call 与 route/navigation/catalog selector exposure 的 source location；两个 verifier可以选择不同 projection，但 source inventory、exclusion rules 和 digest 必须相同。
- **D-SUR-08:** operation capability ID 由 OpenAPI fingerprint join 得出；model/tool selector 的 `capabilityId` 由 Phase 31.1 server response DTO 返回。frontend types、filters 与 exposure checks消费这些值，不允许 hand-authored model/tool capability map，也不允许 caller 在 mutation request 中提交 capability ID。

### Protobuf toolchain 与完整 disposition

- **D-SUR-09:** protobuf toolchain 固定为 `protoc 25.1`、`protoc-gen-go 1.36.11`、`protoc-gen-go-grpc 1.6.2`。仓库维护 machine-readable tool manifest、下载/module checksums 和 manifest digest；bootstrap 只安装到 `.tmp/protobuf-tools/bin`，generation/gate 显式使用该目录，不回退到 host `PATH`。
- **D-SUR-10:** 每个 tracked `.proto` source 和每个 tracked `*.pb.go`/`*_grpc.pb.go` output 必须在 disposition map 中且只出现一次。每个 managed source 声明 include root、exact outputs、plugins/options 和 consumer；source-only entry 需要可验证 consumer/reason。duplicate、orphan、unmanaged generated output、空 glob 和 stale output 一律失败，不能以 ignore list 静默通过。
- **D-SUR-11:** CI `release-gates` 在 protobuf drift gate 前 bootstrap 并核对精确版本；cache key 必须包含 tool manifest digest。gate 在临时目录完整再生并 byte-compare managed outputs，且验证 fresh checkout 不依赖预装全局工具。

### Migration 的三个独立事实

- **D-SUR-12:** migration evidence 分为三个独立 `SurfaceReportV1` producer：`migration-static` 记录 numbered monolith SQL inventory/file-set digest；`migration-ledger` 记录 runtime `schema_migrations(version, checksum)` ordered digest；`migration-replay` 在 fresh monolith PostgreSQL/pgvector 上记录 first apply 与 second no-op replay。三者不得折叠成一个布尔值。
- **D-SUR-13:** static 和 ledger checksum 复用 `src/server/internal/migrations.Checksum` 的 SHA-256 语义；不得修改历史 SQL，也不得引入第二套 ledger identity。microservices SQL 与 ClickHouse SQL作为 excluded/non-monolith inventory 显式 disposition，不得被 monolith replay 暗示为已证明。
- **D-SUR-14:** replay mode 只能是 isolated external database 或 ephemeral Docker database，并必须证明初始 ledger 为空、第一次应用完整、第二次 `applied=0` 且全部 skipped、最终 ledger count/digest 与 static inventory 相等。无 DB 且 Docker 不可用、外部 DB 不新鲜、缺少 `psql` 或无法读取 ledger 都产生 `migration_replay_unavailable`/failure report 并非 skip。

### Nested reports 与唯一 aggregate owner

- **D-SUR-15:** 所有 producer 通过 Phase 31 adapter API 写嵌套 `SurfaceReportV1`。Phase 31.2 只注册并产出自己拥有的 `http-runtime`、`frontend-transport`、`frontend-exposure`、`protobuf`、`migration-static`、`migration-ledger` 和 `migration-replay` details；`build-identity` registration/report 来自 Phase 31，`readiness`/`deployment` registrations/reports 来自 Phase 31.1。本阶段不得恢复 umbrella 早期的 flat report shape。surface-specific data 只能进入已注册的 `evidence.details` schema；producer 不得接受 caller supplied release commit、contract digest、profile 或 evidence class。
- **D-SUR-16:** aggregate 对每个 nested input 做 schema validation、trusted release identity exact-match、唯一 `(surface, canonicalSource, consumer, version)` key、details allowlist、no-skip 和 pass outcome 校验。exact required-surface set 固定为 `build-identity`、`readiness`、`deployment`、`http-runtime`、`frontend-transport`、`frontend-exposure`、`protobuf`、`migration-static`、`migration-ledger` 和 `migration-replay`；missing、extra、duplicate 或折叠 surface 都失败。readiness 输入必须由 Phase 31.1 Go inspector 生成；Python aggregate 不读取 readiness snapshot 后自行实现 freshness。
- **D-SUR-17:** `scripts/verify-quality-gates.sh` 是唯一直接调用 `scripts/verify-release-contract.sh` aggregate 的 parent gate。固定 DAG 为 `CI/check/commercial -> check.sh docs/all -> verify-quality-gates.sh -> verify-release-contract.sh -> surface producers`。其他 parent 只验证 wiring；aggregate 不得反向调用 `check.sh`、`test.sh`、quality 或 commercial，且一个 aggregate run 内每个 expensive producer 只执行一次。
- **D-SUR-18:** focused developer commands可以直接运行单个 producer，但 release parent 不得绕过 aggregate。最终 identity-bearing aggregate 只允许在提交后的 clean checkout 或 CI 运行；开发期 dirty-state 行为在临时 clean Git fixture 验证，最后一次真实 `HEAD` gate 必须在 clean commit 上通过。

### Product exposure、redaction 与证据上限

- **D-SUR-19:** product exposure verifier覆盖 router entries、workspace/console/admin navigation、公开 marketing links、model/tool selectors 与 generated client exports。它消费 sidecar、release projection 和 server catalog output；excluded surface 不出现，conditional surface 只在当前 readiness enabled 时出现，Admin full inventory 不被误判为公开承诺。
- **D-SUR-20:** machine reports 与 operator docs 只允许 repository-relative paths、stable IDs、digests、counts、tool versions、error classes 和 remediation refs。credentials、Authorization/Cookie、query secrets、internal target URLs、原始 response bodies 和仓库外 evidence path 不得进入公开输出；文档只能声明 E1/E2 progress。

### the agent's Discretion

- AST extractor、surface adapters、aggregate implementation 的确切 `scripts/` 文件拆分由 planner 决定，但必须保持单次扫描、单次 aggregate、结构化 output 和上述 ownership。
- runtime descriptor 的 Go type 名、OpenAPI capability extension key 名及 sidecar artifact 的 `.tmp` 路径可按现有命名约定选择；字段语义和双向比较维度不得缩减。
- 当前 duplicate/orphan proto source/output 可以删除、合并或纳入 managed generation；最终 disposition 必须 total、unique、deterministic，不能保留未解释项。

</decisions>

<code_context>
## Existing Code Insights

### Reusable assets

- OpenAPI verifier已有 370-operation derived manifest 的 bidirectional key comparison，runtime test已有 runtime-to-manifest 与 manifest-to-runtime registration checks；两者需要扩展 fingerprint dimensions，而不是另建 route list。
- frontend 已安装 TypeScript，shared `HttpClient`、SSE parser、upload helper 与 route entry arrays 可作为 AST symbol-resolution anchors；当前没有 compiler-API inventory 或 generated consumer。
- generated Go protobuf headers已经记录 generator/protoc versions；当前 Makefile 只有六组 source-to-internal-output commands，适合迁移到 manifest-driven loop。
- migration runtime 已按 filename 读取 SQL、SHA-256、检查 ledger checksum mismatch 并排序；replay script已有 fresh Docker fallback 和 second-run no-op 基线。
- shell gates统一使用 `set -euo pipefail`，fixture families普遍使用 temp dir + one-field mutation + expected nonzero，可复用于 sidecar/report/proto/migration negative cases。

### Current blockers to close

- OpenAPI/manifest/runtime parity 目前不比较 server-core capability/media/schema；frontend transport inventory 也不提供可与 core join 的 encoder/decoder/event extension。
- markdown export frontend走固定 JSON decoder，现有 API test只 mock `get()`，未经过真实 shared client。
- production transports与 product exposure没有共同 inventory；新增 transport 可以逃过现有 gate。
- protobuf source/output集合不完整受 Makefile/CI 管理，CI未安装 pinned toolchain。
- migration static gate只检查 filename；replay没有 typed report/ledger digest，也未接入唯一 aggregate。
- current gate graph在 `check.sh docs` 内既调用 quality gate，又直接调用 OpenAPI/migration gate；Phase 31.2 必须消除 aggregate 递归和重复执行。

</code_context>
