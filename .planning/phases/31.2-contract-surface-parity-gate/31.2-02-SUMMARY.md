# Phase 31.2 Plan 02: HTTP Runtime Registrar And Report Summary

**Three router-owned operations now use one same-source registrar, exact-join the compare-only OpenAPI projection, and feed a trusted typed `http-runtime` report contract with fail-closed snapshot mutations.**

## Accomplishments

- Added a closed `RouteSurfaceRegistration`/`RouteSurfaceDescriptor`/`RouteSurfaceRegistrar` API that derives immutable metadata, composes declared policies, and mounts an exact method/path handler from the same Go value.
- Migrated the admin readiness, app readiness-capabilities, and workspace WebSocket mounts through the registrar and exposed an injected factory seam for snapshot capture.
- Updated legacy manifest behavior tests to decode v2 `scope`, `operations`, and `routeSamples` without restoring a top-level `routes` authority, then proved subset parity in both directions.
- Registered exact seven-field `http-runtime` details in the shared report registry and added trusted repository-local pass/fail report construction with no writer or output ownership.
- Added independent snapshot mutations for mount/descriptor splits, policy failures, core/media drift, exclusions, browser fields, direct ServeMux bypass, and empty discovery.

## Decisions Made

- The runtime subset is intentionally nonempty but incomplete. Full 17-owner route parity is reserved for Plans 13, 14, and 15.
- Production registration never reads or embeds OpenAPI/manifest JSON. Go declarations remain runtime authority; manifest v2 is a separately loaded comparison input.
- Capability IDs must be present in an explicit registrar allowlist. Unknown capabilities fail before mounting.
- Snapshot remains `[]RouteSurfaceDescriptor` as planned; an internal mount/descriptor mismatch makes it empty so downstream comparison cannot pass vacuously.
- HTTP report outcome is derived from `HTTPRuntimeObservation`: pass has empty drift/errors, while fail uses only `drift.incompatible` and `http_runtime_parity_failed`.
