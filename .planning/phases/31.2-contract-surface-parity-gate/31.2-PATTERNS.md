## 1. Production-only AST Sidecar

### Role and ownership

One TypeScript compiler Program produces one immutable sidecar per source digest. Transport parity and product exposure are projections over this artifact; neither verifier rescans TypeScript.

Recommended artifact shape:

```json
{
  "schemaVersion": "frontend-surface-sidecar/v1",
  "sourceScope": {
    "root": "src/web/src",
    "include": ["**/*.ts", "**/*.tsx"],
    "excludeKinds": ["test", "test-support", "fixture", "mock", "snapshot"],
    "generatedPolicy": "consumer-only",
    "filesScanned": 125,
    "sourceDigest": "sha256:64-lowercase-hex"
  },
  "extractor": {
    "name": "oblivious-frontend-surface",
    "typescriptVersion": "5.9.3",
    "configDigest": "sha256:64-lowercase-hex"
  },
  "operations": [],
  "exposures": [],
  "generatedConsumers": [],
  "unresolved": []
}
```

`filesScanned` is evidence, not a hardcoded expectation. The gate requires it and `operations.length` to be nonzero, verifies every discovered transport call has exactly one classification, and requires `unresolved=[]`.

### Exposure entry

```json

    "column": 3

  "capabilitySource": "release-projection"

```

For model/tool selectors, `capabilitySource` must be `server-catalog`, and the AST record points to the DTO field read. A literal TS lookup from model/tool ID to capability ID is incompatible.

### Compiler resolution rules

1. Build the Program from the production tsconfig and canonical absolute root, then emit only repository-relative paths.
2. Classify files from normalized path segments and suffixes before visiting calls.
3. Use the type checker to resolve aliases, imported wrappers, object methods, constants and template expressions.
4. Normalize path parameters to OpenAPI `{name}` form; preserve query key set separately if it affects operation identity.
5. Resolve wrapper declarations (`client`, `streamText`, upload, SWR fetcher) and call sites. An unknown wrapper that reaches `fetch` is unresolved, not `raw-fetch` by guess.
6. Scan generated modules only for stale imported fingerprints/exports; never count generated calls toward production operation coverage.
7. Keep negative fixture roots outside `src/web/src`; fixture scan uses an explicit alternate root and cannot affect production counts.

## 2. Server Core And Frontend Transport Fingerprints

### Taxonomy

| Protocol | Kind | Encoder | Decoder/event identity |
|---|---|---|---|
| HTTP | `http-client` | `none`, `json`, `form-data`, `raw` | `json-envelope`, `text`, `raw-response`, `none` |
| HTTP | `raw-fetch` | same | same; only an approved shared wrapper may own this kind |
| HTTP | `swr` | normally `none` | underlying operation decoder |
| HTTP | `multipart-upload` | `form-data` | declared response decoder |
| SSE | `sse-stream` | `json` or `none` | `sse-text` plus declared event names |
| SSE | `event-source` | `none` | declared event names |
| WebSocket | `websocket` | `websocket-json` or `raw` | inbound/outbound event names |

### Canonicalization and ownership

The server-core fingerprint is owned by OpenAPI, the derived manifest and the Go runtime descriptor. Its digest is SHA-256 over canonical JSON with sorted keys and arrays:

```text
method + normalizedPath + operationId + security + csrf + capabilityId
+ request(mediaType, schemaRef)
+ response(status, mediaType, schemaRef)
```

The frontend sidecar joins to that core and adds a transport extension owned only by the browser/client projection:

```text
protocol + kind + request.encoder + response.decoder + sorted event identities
```

The full frontend fingerprint digest covers the core plus this extension. Go runtime descriptors never author browser encoder, decoder or event identity. The transport verifier proves the extension is compatible with the core media/schema contract and reports any unresolved mapping as `incompatible`.

- Media types compare lowercase base types; parameters are parsed, not string-split assumptions. `text/markdown` is compatible with `text/markdown; charset=utf-8` when charset is allowed by the decoder.
- Request/response schema identity is canonical `$ref` or a deterministic inline schema digest. TypeScript generic names alone are supporting diagnostics, not canonical schema identity.
- Every success status documented by OpenAPI requires a runtime disposition. A client call may declare one selected success response only when the other statuses share the same core media/schema and compatible decoder; otherwise it must model the alternatives.
- Unknown method/path in the core or unknown encoder/decoder/event identity in the frontend extension produces `incompatible`, never a warning.

## 3. Typed `ResponseDecoder`

Preserve the existing shared error path while making success decoding explicit:

```ts
export type ResponseDecoder<T> = {
  readonly id: 'json-envelope' | 'text' | 'raw-response' | 'none';
  readonly accept: string;
  accepts(contentType: string): boolean;
  decode(response: Response): Promise<T>;
};

export type HttpClient = {
  request<T>(path: string, init?: RequestInit, decoder?: ResponseDecoder<T>): Promise<T>;
  get<T>(path: string, init?: RequestInit, decoder?: ResponseDecoder<T>): Promise<T>;
  post<T>(path: string, body?: unknown, init?: RequestInit, decoder?: ResponseDecoder<T>): Promise<T>;
  put<T>(path: string, body?: unknown, init?: RequestInit, decoder?: ResponseDecoder<T>): Promise<T>;
  delete<T>(path: string, init?: RequestInit, decoder?: ResponseDecoder<T>): Promise<T>;
};
```

Compatibility rules:

- Default decoder remains `json-envelope`; it sends `Accept: application/json`, validates JSON-compatible response media, calls `response.json()`, then `unwrapEnvelope<T>()`.
- `textResponseDecoder('text/markdown')` sends `Accept: text/markdown`, parses `Content-Type` case-insensitively, accepts charset, calls `response.text()`, and returns the string directly.
- caller headers may add values but may not contradict decoder `Accept`; a contradiction fails before transport.
- non-2xx responses use the shared structured error parser. JSON error envelopes preserve stable code/data; non-JSON bodies are not copied into public errors.
- 204 uses `none`; it must not invoke a body decoder.

The markdown regression test must construct the real client with an injected `fetchFn` returning a real `Response('# ...', {headers:{'Content-Type':'text/markdown; charset=utf-8'}})`, then call `createChatApi(client).exportConversationMarkdown()`. Mocking `client.get` does not prove decoder behavior.

## 4. HTTP Runtime Descriptor and Surface Adapter

Use a typed descriptor alongside route registration:

```go
type RouteSurfaceDescriptor struct {
    Method       string
    Path         string
    OperationID  string
    Security     string
    CSRF         bool
    CapabilityID string
    Request      MediaSchemaRef
    Responses    []StatusMediaSchemaRef
}
```

Registration and descriptor must originate from one declaration. A route cannot be mounted without a descriptor, and a descriptor cannot exist without a mounted route. OpenAPI remains schema authority; Go descriptor stores refs/digests required to prove handler binding, not copied schema bodies.

`RouteSurfaceDescriptor` implements only the server-core fingerprint. The frontend AST sidecar supplies `transport.kind`, encoder, decoder and event identities, then joins them to the core by operation ID plus normalized method/path and validates media/schema compatibility. Neither side may invent the other's fields.

The adapter receives trusted identity and emits Phase 31's nested report:

```text
OpenAPI projector + derived manifest + runtime descriptors
  -> compare missing/extra/incompatible
  -> registered HTTP details schema
  -> SurfaceReportV1 writer
```

Do not let Python parse Go source as the final runtime truth. Existing source scans remain useful as a completeness guard for declared registrars, while runtime descriptor tests prove mounted behavior.

## 5. Protobuf Tool Manifest, Bootstrap and Disposition

Recommended manifest/schema shape (integrity format rules are shown rather than future checksum values):

```json
{
  "schemaVersion": "protobuf-toolchain/v1",
  "tools": {
    "protoc": {
      "version": "25.1",
      "artifact": "protoc-25.1-linux-x86_64.zip",
      "integrity": {"algorithm": "sha256", "valueFormat": "64 lowercase hex"}
    },
    "protoc-gen-go": {
      "version": "1.36.11",
      "module": "google.golang.org/protobuf/cmd/protoc-gen-go",
      "integrity": {"algorithm": "go-module-sum", "valueFormat": "h1 base64"}
    },
    "protoc-gen-go-grpc": {
      "version": "1.6.2",
      "module": "google.golang.org/grpc/cmd/protoc-gen-go-grpc",
      "integrity": {"algorithm": "go-module-sum", "valueFormat": "h1 base64"}
    }
  },
  "dispositions": []
}
```

Each disposition has exactly one source and explicit outputs:

```json
{
  "source": "api/proto/agent.proto",
  "mode": "managed",
  "includeRoot": ".",
  "outputs": [
    "api/proto/agent.pb.go",
    "api/proto/agent_grpc.pb.go",
    "src/server/internal/grpc/agentv1/agent.pb.go",
    "src/server/internal/grpc/agentv1/agent_grpc.pb.go"
  ],
  "consumers": ["src/server/internal/grpc/agentv1"],
  "plugins": ["go", "go-grpc"]
}
```

Rules:

- manifest validator discovers tracked sources/outputs from Git and proves set equality with dispositions; no glob may match zero silently.
- an output appears once and only once. A source-only entry needs an explicit compile/descriptor consumer and zero generated outputs; duplicate/orphan source is removed or fully managed, never ignored.
- bootstrap verifies archive/module checksum and exact `--version`, writes only `.tmp/protobuf-tools/bin`, and emits a deterministic manifest digest.
- generation uses explicit tool paths, an empty temp tree, declared include roots/options and stable locale. Compare generated bytes to every managed tracked output.
- CI cache key includes OS/arch plus manifest digest. Cache hit still verifies versions before generation.

## 6. Migration Surface Adapters

Three adapters share identity but have distinct details schemas. Each full `SurfaceReportV1` sets `evidence.environment` to a non-secret class such as `local-docker` or `ci-postgres`, and `evidence.mode` to `static`, `ledger` or `replay`; the fragments below show only registered `details`:

```json
{
  "surface": "migration-static",
  "details": {
    "databaseKind": "postgresql-pgvector",
    "fileCount": 112,
    "inventoryDigest": "sha256:ordered-version-checksum-digest"
  }
}
```

```json
{
  "surface": "migration-ledger",
  "details": {
    "databaseKind": "postgresql-pgvector",
    "rowCount": 112,
    "ledgerDigest": "sha256:ordered-version-checksum-digest"
  }
}
```

```json
{
  "surface": "migration-replay",
  "details": {
    "databaseKind": "postgresql-pgvector",
    "replayMode": "docker-ephemeral",
    "initialLedgerRows": 0,
    "firstApply": {"applied": 112, "skipped": 0},
    "secondApply": {"applied": 0, "skipped": 112},
    "ledgerDigest": "sha256:64-lowercase-hex"
  }
}
```

Counts above illustrate the current snapshot and are computed at runtime. Digest input is a sorted sequence of exact filename/version plus `migrations.Checksum(sqlBytes)`; ledger uses the same sequence. The adapter never edits SQL or normalizes its bytes.

External replay databases must be isolated/fresh and prove zero initial ledger rows. If isolation cannot be proven, fail before apply. Missing Docker/DB/psql yields a failure report with `migration_replay_unavailable`, nonzero producer exit, and no accepted skip.

## 7. Nested `SurfaceReportV1` Consumption

Adapters do not build identity fields. They receive a Phase 31 `ReportContext` from the trusted resolver and only provide:

```text
surfaceIdentity + drift + registered evidence.details + local outcome
```

The shared writer fills `schemaVersion`, `releaseIdentity`, `evidence.class/environment/mode/checkedAt/toolVersions`, validates the details registry, and atomically writes. Aggregate rejects:

- any non-`surface-report/v1` input or flat legacy fields;
- release identity not exactly equal on commit/tree/contract/profile/dirty/evidence class;
- duplicate `(surface, canonicalSource, consumer, version)`;
- missing/extra required surface, folded surface, or unregistered details key;
- non-empty `skippedChecks`, failed outcome, drift arrays with entries, partial/temp file;
- public diagnostics containing secret-like keys, credentials, raw external URLs/bodies or host evidence paths.

Recommended aggregate envelope embeds validated reports without flattening them:

```json
{
  "schemaVersion": "release-contract-aggregate/v1",
  "releaseIdentity": {"$ref": "BuildIdentityV1 + deploymentProfile"},
  "reports": [{"$ref": "SurfaceReportV1"}],
  "outcome": {"result": "pass", "errorCodes": [], "skippedChecks": []}
}
```

The exact required surface IDs are `build-identity`, `readiness`, `deployment`, `http-runtime`, `frontend-transport`, `frontend-exposure`, `protobuf`, `migration-static`, `migration-ledger` and `migration-replay`. Readiness is obtained by invoking the Phase 31.1 Go inspector. The aggregate compares identity and outcome only; it does not parse timestamps to re-evaluate freshness.

## 8. Aggregate DAG and Anti-recursion

### Fixed graph

```text
verify-commercial-completion.sh
        |
        v
check.sh docs/all <--- CI release-gates
        |
        v
verify-quality-gates.sh
        |
        v
verify-release-contract.sh
        |
        +--> foundation build report
        +--> deployment report
        +--> HTTP/runtime
        +--> frontend sidecar -> transport + exposure
        +--> protobuf
        +--> migration static -> ledger -> replay
        +--> readiness inspector
```

### Enforcement patterns

- `verify-release-contract.sh` owns an explicit ordered producer registry for the exact upstream and Phase 31.2 surface set and executes each entry exactly once, capturing exit status and report path.
- quality is the only parent script with an executable aggregate call. `check.sh`, commercial and CI are tested to reach it transitively and contain no direct aggregate invocation.
- aggregate source is checked to contain no calls to `check.sh`, `test.sh`, quality or commercial. Runtime fixture records producer invocation IDs and fails duplicates.
- a producer failure remains visible even if it wrote a failure report; aggregate returns nonzero after validating available reports.
- developer-focused producer scripts remain independently runnable and do not invoke aggregate.
- output directory is new/empty per run; stale reports cannot satisfy required-surface coverage.

## 9. TDD and Fresh-checkout Pattern

For each plan:

1. Add a minimal negative fixture or focused unit test that fails for the intended drift.
2. Prove the selector discovers at least one test/call/source before interpreting result.
3. Implement the smallest producer/adapter/consumer change.
4. Run focused test, related surface gate, `git diff --check` and contradiction/redaction scan.
5. Commit atomically. Identity-bearing validation then runs against clean real `HEAD`; failed commits are repaired with a new commit before push.

AST and protobuf fresh-checkout tests use declared install/bootstrap only. Migration fresh replay uses unique DB/container identity and unconditional cleanup. No untracked `.tmp` artifact is accepted as canonical input across runs.

## Planner Guardrails

1. Keep the nine slices from RESEARCH; do not merge proto/migration/aggregate into one oversized plan.
2. Do not re-author Phase 31 report identity or Phase 31.1 catalog/readiness semantics.
3. Do not replace TypeScript compiler AST, OpenAPI parser, protoc or runtime ledger with regex-based source interpretation.
4. Do not treat current host tools, Docker availability, fixture results or repository-local reports as E3/E4 proof.
5. Do not leave duplicate producer calls in parent gates or allow zero-match commands to report green.
