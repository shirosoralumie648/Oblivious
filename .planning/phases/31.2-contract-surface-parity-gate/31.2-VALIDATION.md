## TDD Protocol

Every plan follows RED -> GREEN -> REFACTOR -> VERIFY:

1. Write one focused failing test/fixture for the exact missing or drifted field.
2. Run it and prove the selector matched at least one test/source/call before accepting the failure.
3. Implement the minimum production change; do not broaden authority or create a parallel map.
4. Run the focused test, related producer gate, aggregate fixture subset and `git diff --check`.
5. Commit atomically. For identity-bearing behavior, run the real-HEAD gate only after the commit and clean-worktree check.

A Go `-run` regex, Vitest filter, source glob or AST selector that matches zero items is failure. Fixture wrappers must print/assert discovery counts; they cannot infer success only from exit code zero.

## Focused Test Matrix

### AST and media

- Production scan includes `HttpClient`, direct/injected fetch, SWR, multipart, SSE/`streamText`, EventSource and WebSocket branches.
- Test/support/fixture/mock/snapshot calls are excluded; generated files are consumer-only.
- Constants, aliases and static templates resolve; unresolved dynamic path/method/media/decoder fails.
- `operations.length > 0`, `filesScanned > 0`, required wrapper sentinels are found, and fixture branch counts are asserted.
- Markdown sends `Accept: text/markdown`, accepts `text/markdown; charset=utf-8`, calls `Response.text()`, and never calls JSON unwrap.
- JSON envelope, non-OK structured error, malformed/redacted error, SSE and 204 behavior remain covered.

### OpenAPI/runtime

- server-core method/path, operation ID, security/CSRF, capability, request media/schema and all success response status/media/schema identities match in both directions.
- frontend extensions join the core and validate transport kind, request encoder, response decoder and event identity against its media/schema; Go runtime descriptors contain none of those browser-owned fields.
- excluded route has no registration; every registered descriptor has a canonical operation; no descriptor-only entry.
- route manifest generation is deterministic and contains no second handwritten schema body.
- wrong charset/base media, incompatible frontend decoder/encoder, event mismatch and ad hoc runtime schema copy are negative cases.

### Protobuf regeneration

- bootstrap verifies `protoc 25.1`, `protoc-gen-go 1.36.11`, `protoc-gen-go-grpc 1.6.2` and manifest/checksums.
- fresh checkout deliberately removes global tools from `PATH`; only `.tmp/protobuf-tools/bin` is accepted.
- Git-discovered tracked `.proto` and generated outputs equal the disposition sets exactly; duplicate/orphan/empty set fails.
- every managed source regenerates into a new temp tree and byte-compares every declared output.
- CI cache key includes tool manifest digest and version verification runs on cache hit.

### Migration replay

- static inventory and runtime ledger digest exact ordered `(version, checksum)` pairs, not row count alone.
- isolated DB starts with zero ledger rows; first apply is complete; second apply applies zero; final count/digest equal static.
- historical SQL mutation, missing row, extra row, checksum mismatch, partial transaction and reused external database fail.
- without a DB URL and without reachable Docker the producer emits a nested failure report, stable `migration_replay_unavailable`, and nonzero exit; it must not record an accepted skip.
- unique container/database identity and unconditional cleanup are verified after success and failure.

### Aggregate splice/skip/redaction

- exact release commit, source tree, contract digest, deployment profile, dirty flag and evidence class match across all nested inputs.
- exact required set is `build-identity`, `readiness`, `deployment`, `http-runtime`, `frontend-transport`, `frontend-exposure`, `protobuf`, `migration-static`, `migration-ledger` and `migration-replay`; missing, extra, duplicate or folded reports fail.
- every required `(surface, canonicalSource, consumer, version)` occurs once; duplicate, stale directory or missing producer fails.
- flat legacy reports, unregistered details, non-empty drift, failed outcome and any committed `skippedChecks` fail.
- producer exit status is preserved even when an atomic failure report exists; unwritable output leaves no temp/partial file.
- Authorization/Cookie/key/secret/token values, credential-bearing URLs, raw body and external evidence path are rejected/redacted.
- tracked docs contain no exact-current-commit pass claim and never elevate E1/E2 to target/commercial readiness.

## Fresh-checkout Paths

### AST/frontend

Create a temporary clean checkout at the plan commit, run `pnpm install --frozen-lockfile`, then run sidecar generation twice. Digests and bytes must match; untracked workspace sidecars cannot be inputs.

### Protobuf

Create a temporary clean checkout with global protoc/plugin locations removed from `PATH`. Run only the declared bootstrap, validate tool versions/checksums, regenerate to a new temp directory and compare all managed outputs.

### Migration

Use a unique ephemeral pgvector container/database or a provably isolated external database. Record environment class only, never connection URL. Run first apply, second replay, ledger query and cleanup in one bounded fixture.

### Final clean commit

During implementation, identity checks use temporary clean Git fixtures. After each atomic plan commit, focused tests may run normally. Before Phase 31.2 close:

1. `git status --porcelain` must be empty.
2. Run `bash scripts/verify-release-contract.sh` against real `HEAD`.
3. Run `bash scripts/verify-quality-gates.sh`; it must invoke aggregate exactly once.
4. Run relevant server/web suites and `git diff --check`.
5. If any repair changes tracked bytes, commit it and repeat from step 1 before push.
