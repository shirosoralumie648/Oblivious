## Decisions Made

- Applied/skipped counts are computed only from canonical identity rows before apply, after first apply, and after second apply. Migration command prose may be retained as redacted diagnostics but never changes the verdict.
- Failure evidence uses sentinel unavailable counts and `migration_replay_unavailable`, contains no skips, and cannot convert an unavailable producer into a zero exit.
- Docker sessions execute `psql` inside the ephemeral database container; external sessions require host `psql` and accept connection material only through a named environment variable.
- Success is published after cleanup so `cleanupResult: succeeded` describes verified post-session state rather than cleanup intent.
