## Summary

The cumulative Phase 31 through 31.2 range was reviewed at standard depth using committed `HEAD` snapshots. The release gate is not safe to ship: external migration replay can mutate a populated caller-owned database, the frontend compiler sidecar can miss uncontracted transports while reporting closure, and late readiness denials can strand quota reservations when compensation fails. Two additional protocol/input-hardening defects should also be corrected.

No test-pass claim is made by this review.

## Narrative Findings (AI reviewer)

## Critical Issues

### CR-01: External replay can mutate a non-fresh database and falsely report cleanup

**Classification:** Critical (BLOCKER)

**File:** `scripts/verify-migration-replay.sh:288-295`, `scripts/verify-migration-replay.sh:316-357`, `scripts/verify-migration-replay.sh:490-506`, `src/server/migrations/0027_tenant_scope_core_domains.sql:224-258`

**Issue:** External mode calls only `SELECT 1` before labeling a caller-provided database `external-isolated`. Freshness is then inferred solely from an absent or empty `schema_migrations` ledger. A database with pre-existing application tables/data and an empty ledger passes that check, after which the real migration binary runs twice. Existing migrations update and delete customer rows, including quota consolidation in migration 0027. Cleanup only removes Docker resources, yet external mode inherits `cleanup_result="succeeded"` and leaves the caller-owned database fully migrated. This creates a direct data-loss/corruption risk and does not satisfy the phase's "provably fresh external database" boundary.

**Fix:** Before any external migration, fail unless the entire candidate namespace has no non-system schemas, relations, sequences, or application data. Prefer creating and owning a disposable database/schema with a unique name and verified teardown. Emit cleanup success only after that owned database/schema has been removed. Add a fixture containing an empty ledger plus a pre-existing application table/row and assert rejection before `cmd/migrate` executes.

### CR-02: Frontend transport extraction can be bypassed while the parity gate stays green

**Classification:** Critical (BLOCKER)

**File:** `scripts/frontend_surface_sidecar.mjs:538-606`

**Issue:** Transport discovery recognizes direct calls by syntactic spelling (`fetch`, `fetchFn`, `streamText`, etc.) and selected property names. It does not resolve a transport alias or a property call such as `globalThis.fetch`; those calls return no transport kind and are silently skipped by the production visitor. Separately, `invocationPathMatches` returns `true` for every nonliteral expression, so unresolved variables and incorrect template expressions are accepted rather than entering `unresolved`. An existing owner can therefore retain one valid classified call while adding an aliased raw network call, and the owner closure/source digest still reports success. This defeats the release gate's core purpose and permits uncontracted provider/auth/billing transports to escape parity evidence.

**Fix:** Resolve callees through TypeScript symbols and declarations into a bounded transport call graph, including imported/locally aliased functions, object methods, `globalThis.fetch`, and approved wrappers. Resolve constants and static template expressions to a path shape; send any dynamic or ambiguous path/method to `unresolved`. Add mutations for aliased fetch, `globalThis.fetch`, wrapper aliases, wrong static templates, and truly dynamic paths, each required to fail the production sidecar.

### CR-03: Readiness compensation discards refund failures and can strand billable quota

**Classification:** Critical (BLOCKER)

**File:** `src/server/internal/relay/router.go:575-596`

**Issue:** The newly added pre-provider readiness rechecks run after organization and API-token quota have been preauthorized. When either recheck denies the request, both refund calls discard their returned errors and the function returns only the readiness error. A storage outage or partial refund can therefore leave one or both reservations charged/held with no durable retry signal, while callers are told only that readiness was stale. The tests assert invocation counts with always-successful stubs and do not cover compensation failure. This violates the platform's billable-operation recoverability invariant and creates financial/accounting inconsistency.

**Fix:** Centralize compensation in a helper that attempts both refunds, records each result, and returns a joined/typed compensation error. Persist failed compensation to a retryable outbox or equivalent durable reconciliation path before returning. Add tests where organization refund, token refund, and both refunds fail, and assert no failure is hidden behind the readiness error.

## Warnings

### WR-01: SSE framing does not recognize CRLF event boundaries

**Classification:** Warning

**File:** `src/web/src/services/http/stream.ts:43-58`

**Issue:** The parser searches only for `\n\n`. Valid SSE streams may delimit events with `\r\n\r\n`; those frames accumulate until EOF and multiple events are then parsed as one frame. This can merge chunks, suppress `[DONE]`, or mis-handle an `event: error` frame. The current tests cover LF framing only.

**Fix:** Scan for a blank line using a CRLF-aware boundary (for example `/\r?\n\r?\n/`) while preserving boundaries split across byte chunks. Add CRLF tests for multiple data frames, `[DONE]`, errors, and delimiters split across reads.

### WR-02: Aggregate symlink rejection checks the resolved target instead of the supplied path

**Classification:** Warning

**File:** `scripts/verify_release_contract.py:260-280`

**Issue:** `validate_report_directory` calls `resolve(strict=True)` before `is_symlink()`. The resolved `Path` represents the target, so the symlink checks at lines 265 and 273 cannot detect that the caller supplied a symlinked report directory/path. Ancestor symlinks are also accepted by `read_json`. This weakens the validator's containment guarantee and leaves a check/use substitution window for standalone or concurrently manipulated inputs.

**Fix:** Reject symlinks on the original directory, each original report path, and relevant ancestors before resolving; for the high-trust read, open relative to a verified directory descriptor with no-follow semantics where supported. Add fixtures for a symlinked report directory, report file, and ancestor directory.
