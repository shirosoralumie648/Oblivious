# Phase 31.2: 契约表面一致性与聚合门禁 - Research

**Researched:** 2026-07-16
**Domain:** HTTP/frontend/protobuf/migration parity and release-gate aggregation
**Requirement:** `RELS-02`
**Confidence:** HIGH for repository-local inventory; upstream Phase 31/31.1 implementation paths remain dependency-bound

## Summary

仓库已有四组可复用基础，但当前都只覆盖 parity 的一部分：OpenAPI 与 370-row route manifest 比较 method/path/security/CSRF/operationId/tags；Go route tests双向确认 manifest route被注册；migration runtime按 SQL bytes 做 SHA-256 ledger校验；quality/commercial gates已有稳定 shell wrapper 与 negative fixture family。[VERIFIED: `scripts/verify_openapi_contract.py:508-576`, `src/server/internal/http/route_surface_test.go:2458-2544`, `src/server/internal/migrations/migrations.go:63-140`, `scripts/check.sh:211-306`]

`RELS-02` 的真实缺口位于“被省略的维度”和“多个局部门禁之间的 ownership”：capability/media/schema 未进入 server-core route parity，frontend encoder/decoder/event extension 没有 production-only compiler AST inventory 或 core join；protobuf只有部分 Makefile generation；migration replay没有 nested typed evidence；`check.sh docs` 目前在 quality gate 之外再次直接运行 OpenAPI/migration checks。Phase 31.2 应扩展现有 canonical owners，并让一个 aggregate消费所有 nested `SurfaceReportV1`，而不是创建第二套 API、catalog、migration 或 readiness truth。

### 2. `export.md` 的已证实 drift

`GET /api/v1/app/conversations/{conversationId}/export.md` 是当前最小可复现 parity bug：

1. OpenAPI 200 response 声明 `text/markdown`。[VERIFIED: `docs/api/openapi.yaml:8001-8022`]
2. Go handler返回 `Content-Type: text/markdown; charset=utf-8` 与 raw markdown bytes。[VERIFIED: `src/server/internal/http/chat_actions_handler.go:204-228`]
3. shared `HttpClient` 无 decoder参数，固定发送 `Accept: application/json`，success path无条件 `response.json()` 后 `unwrapEnvelope()`。[VERIFIED: `src/web/src/services/http/client.ts:21-89`]
4. Chat client调用 `client.get<string>(.../export.md)`，因此真实浏览器路径会把 markdown 当 JSON 解析。[VERIFIED: `src/web/src/features/chat/api.ts:227-228`]
5. 当前“downloads ... as text”测试只 mock `get()` 返回字符串，未调用 `createHttpClient` 或 `Response.text()`，所以测试无法发现 drift。[VERIFIED: `src/web/src/features/chat/api.test.ts:131-138`]

该路径应由 ResponseDecoder 与 AST media fingerprint 的 focused automated test 覆盖，而不是为单个 endpoint添加绕过 shared client 的 raw `fetch`。

### 6. Migration static、ledger 与 replay behavior

Current monolith inventory has 112 root PostgreSQL SQL files. There are also 12 `migrations/microservices/*.sql` and one ClickHouse SQL, but they do not belong to committed monolith replay.

| Layer | Current behavior | Missing typed evidence |
|---|---|---|
| Static | `verify-migration-contract.sh` requires `NNNN_description.sql` and fixes accepted duplicate-prefix sets 0013-0022. | file content checksums、ordered file-set digest、machine output和 non-monolith disposition。 |
| Runtime ledger | `migrations.Apply` sorts files, computes SHA-256, compares existing `schema_migrations.checksum`, fails mismatch, and transactionally records version/checksum。 | ordered ledger digest/report adapter；与 static inventory total equality。 |
| Replay | `verify-migration-replay.sh` uses supplied DB or starts pgvector Docker, runs migrate twice, requires second run `applied: 0`, checks ledger row count。 | initial-empty proof、explicit environment/mode、ledger digest、nested report、aggregate integration。 |

Current replay already fails if Docker is absent/unreachable and no DB URL is set, which matches fail-closed intent. However an external URL is not currently proven fresh, and output is human text only. On this research host Docker daemon is reachable while `MIGRATION_REPLAY_DATABASE_URL` and `TEST_DATABASE_URL` are unset; that is environment availability, not a recorded Phase 31.2 pass.

### 7. Current and target gate call graph

Current execution graph:

```text
.github/workflows/ci.yml release-gates
  -> scripts/check.sh docs
       -> scripts/verify-quality-gates.sh
       -> scripts/verify-openapi-contract.sh
       -> scripts/verify-migration-contract.sh

scripts/verify-commercial-completion.sh
  -> scripts/check.sh docs
       -> same chain above
```

`verify-quality-gates.sh`当前主要对 wiring/content做 static assertions；它尚未调用统一 surface aggregate。若仅把 aggregate新增到 quality而保留 `check.sh` 的 direct OpenAPI/migration calls，同一次 parent run会重复 producer，并可能重复 expensive replay。

Target graph必须是：

```text
CI / commercial / check.sh all
  -> check.sh docs
       -> verify-quality-gates.sh                 # sole direct parent owner
            -> verify-release-contract.sh         # once
                 -> http/runtime adapter
                 -> frontend sidecar + transport/exposure adapters
                 -> protobuf adapter
                 -> migration static/ledger/replay adapters
                 -> readiness Go inspector adapter
```

Aggregate不得调用任何 ancestor。Narrow producer仍可被开发者直接执行，但 `check.sh`、commercial、CI或其他 release parent不得直接执行 aggregate。

## Recommended Plan Decomposition

Nine plans fit the approved 8-10 target while keeping ownership boundaries testable:

1. OpenAPI operation fingerprint and derived manifest schema.
2. Go runtime descriptor plus bidirectional capability/media/schema parity.
3. Production-only TypeScript AST sidecar and transport taxonomy fixtures.
4. Shared `ResponseDecoder` and real markdown export path.
5. Shared sidecar product exposure plus server catalog capability consumption.
6. Pinned protobuf tool manifest/bootstrap and total disposition regeneration.
7. Migration static inventory plus runtime ledger typed adapters.
8. Fresh monolith replay, failure semantics and nested migration report.
9. Aggregate identity/no-skip/redaction rules, sole-owner DAG, CI and operator docs.

## Validation Architecture

### Test layers

| Layer | Framework/shape | Primary proof |
|---|---|---|
| AST unit | Node `node:test` or Vitest invoking TypeScript compiler API | production exclusions, symbol/wrapper resolution, every transport kind, dynamic/unclassified failure |
| Frontend runtime | Vitest with real `createHttpClient` and real `Response` objects | JSON/text/media decoder behavior and `export.md` end-to-end through shared client |
| HTTP contract | Python fixtures + Go `testing` | OpenAPI/manifest/runtime server-core missing/extra/capability/security/media/schema mismatch |
| Frontend core join | TypeScript compiler sidecar + structured fixtures | transport kind/encoder/decoder/event extension compatibility with the server core |
| Protobuf | shell/Node/Python fixture around isolated tool bootstrap | exact versions/checksums, total disposition, temp regeneration, stale/orphan failure |
| Migration | Go tests + shell/Python adapter + real PostgreSQL/pgvector replay | static digest=ledger digest; fresh apply + no-op replay; unavailable environment is failure |
| Aggregate | structured one-field JSON mutations | nested schema, splice, duplicate key, skip, failed producer, secret/redaction and atomic output |
| Wiring | shell fixture and CI YAML assertions | one direct aggregate owner, no ancestor recursion, one execution per producer |

### Required negative fixture families

- HTTP core: missing/extra operation; wrong method/operation/security/CSRF/capability; wrong request media/schema; wrong response status/media/schema; route descriptor omitted or browser decoder copied into Go ownership.
- Frontend extension join: wrong request encoder, response decoder or event identity for a valid core; missing/ambiguous core join; extension attempts to redefine method/path/media/schema.
- Frontend: test-only call excluded; fixture root isolated; generated call not counted as production; unknown wrapper; dynamic path/method; raw fetch; multipart; SSE; EventSource; WebSocket; sidecar zero operations; transport/exposure digest mismatch.
- Decoder: markdown routed to JSON; missing/wrong content type; charset accepted; non-OK JSON envelope preserved; malformed error body redacted.
- Catalog/exposure: client-authored `capabilityId`; selector ignores server capability; excluded nav/client export; conditional surface shown while disabled/blocked.
- Proto: wrong tool version/checksum; absent binary in fresh checkout; source/output missing, duplicate or orphan; generated byte drift; empty disposition glob.
- Migration: changed historical SQL; static/ledger missing/extra/checksum mismatch; non-empty external DB; first apply partial; second replay applies rows; no DB/Docker; ledger unavailable.
- Aggregate: missing/extra/folded foundation build, readiness, deployment or Phase 31.2 surface; cross commit/tree/contract/profile/evidence-class splice; flat report; unregistered details field; duplicate surface key; non-empty skip; failed producer; partial/temp report; credential/internal URL leak; recursive or duplicate gate invocation.

### Fresh-checkout and no-false-green requirements

- AST and protobuf gates run from a temporary `git archive`/clean clone after only declared bootstrap/install steps; neither may use untracked workspace outputs.
- Every matcher/extractor fixture asserts positive discovery count before testing mismatch. A command that selects zero Go/Vitest/AST cases is failure, not pass.
- EventSource may remain zero in production, but the extractor's EventSource branch must detect a fixture caller and then reject its deliberate drift.
- Aggregate requires exact surface IDs `build-identity`, `readiness`, `deployment`, `http-runtime`, `frontend-transport`, `frontend-exposure`, `protobuf`, `migration-static`, `migration-ledger` and `migration-replay`, each with exact execution count one; empty glob, empty report directory, missing/extra/folded surface or zero producers is `surface_schema_invalid`.
- Migration replay is environment-backed automation, not manual sign-off. No DB/Docker produces nonzero `migration_replay_unavailable`; it is never added to `skippedChecks` as an accepted result.
- Final real-HEAD aggregate runs only after an atomic commit and clean `git status --porcelain`; identity-bearing output from a dirty implementation checkout is diagnostic-only.
