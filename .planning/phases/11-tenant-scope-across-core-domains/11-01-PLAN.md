<threat_model>
## Threat Model

| Threat | Severity | Mitigation in this plan |
|--------|----------|-------------------------|
| Client submits `organizationId` or `workspaceId` to access another tenant. | High | Use session-derived active organization only; tests send misleading IDs and assert denial/no mutation. |
| Existing user-owned tables become cross-tenant after users join multiple organizations. | High | Add `organization_id` to user-owned parent tables and filter every representative query by session organization. |
| Legacy workspace data becomes unreachable after tenant migration. | High | Backfill deterministic organizations from workspaces and keep workspace columns during Phase 11. |
| Chat/Agent/Relay usage records lose tenant identity. | High | Carry organization ID into usage/quota/billing session writes and console aggregation. |
| Marketplace public browse is accidentally made private or publisher data remains user-only. | Medium | Keep public search global; scope publisher, install, review, and analytics paths by organization. |
| Tests prove only happy paths, not isolation. | High | Add DB-backed cross-tenant HTTP tests for representative read and write paths across every required domain. |
| Phase 11 claims future commercial work. | Medium | Summary must list v05-v08 residual work explicitly and keep goal active. |
</threat_model>
