<threat_model>
## Threat Model

| Threat | Severity | Mitigation in this plan |
|--------|----------|-------------------------|
| Organization membership becomes cosmetic and does not enforce roles. | High | Add role checks in tenant service and HTTP handlers; tests cover admin/member/owner denial paths. |
| Organization loses its last owner. | High | Transactional ownership and removal rules prevent demoting/removing the only active owner. |
| Invitation tokens leak from the database. | High | Store only token hashes; return raw token once from create/invite response. |
| Sensitive role/ownership changes happen without audit evidence. | High | Write mutation and audit entry in one transaction where practical; fail mutation when audit insert fails. |
| Cookie-auth mutating routes remain CSRFable. | High | Require `X-CSRF-Token` for session/admin/app mutating routes and add route-surface tests. |
| Brute force login/register/password reset is still possible. | High | SQL-backed rate limiter rejects over-budget attempts before expensive work and returns 429. |
| Weak passwords remain accepted due historical tests. | Medium | Update tests and fixtures to use strong passwords; add policy unit tests. |
| Stale sessions retain old tenant privileges. | Medium | Rotate current session on invitation acceptance and revoke affected sessions on role/removal/ownership changes. |
</threat_model>
